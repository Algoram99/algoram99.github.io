AI Agent Structured Logging: 5 Patterns, 4 Anti-Patterns, and a Drop-In JSONL Logger

Every LLM agent eventually produces a session record — the question is whether that record is a single append-only JSONL file you can grep, audit, attribute, and re-run, or a stack trace stringified with JSON.stringify and lost to log-rotation three days after the bug shipped. This post is the structured-logging architecture I wish I had on the first agent whose debug session started with the words “I cannot reproduce this because the log file rotated three days ago.”

TL;DR

Five patterns that work: JSONL session record (one file per session, one JSON line per event, append-only, never rewritten, never pretty-printed), schema-first with JSON Schema validation (every event validates against a versioned schema in CI before it can be written, so drift between runs is impossible by construction), eight-event taxonomy (request_started, tool_called, tool_returned, context_evicted, budget_decided, compacted, completed, failed — eight verbs, no more, no fewer, every LLM call and every side effect maps to exactly one of them), write-time PII redaction (deterministic sha256-prefixed masks applied before the line hits disk, so secrets and PII never enter the log in the first place — the redactor is the gate, not a post-hoc scrubber), and line + turn + token_offset searchable index (every line carries its sessionId, turn, tokenOffset, and a content-hash eventId so a query like “show me the budget_decided events for session X that triggered an eviction” resolves in <100ms on a 1,000-event file). Four anti-patterns that ship unreadable, unrotatable, unsearchable logs: prettyprint-the-prompt (the agent dumps the full system prompt + tool catalog + conversation history on every call, the log balloons to 80% of the disk, and the PII redactor is impossible to retrofit because the data is already on disk), log-only-the-response (the framework’s default logger only sees the final LLM response, the tool-call trail is lost, the cost attribution layer cannot attribute the $0.18 LLM call to the 4 tool calls that caused it), json-per-call-no-schema (the agent calls JSON.stringify({...}) per event with no schema, the keys drift between versions, the cost-attribution layer silently returns NaN for 12% of calls because tokens_in became tokenIn in a refactor), and local-file-only-no-rotation (the agent writes to /var/log/agent.log with no rotation, no compression, no query path, the disk fills at 2am on a Saturday and the agent is silently down for 6 hours before anyone notices). The post includes a 95-line drop-in TypeScript structured-logger runtime, 8 selftest cases, and a Woodpecker CI gate that fails any agent runtime change that regresses the eight-event taxonomy or ships a line that does not validate against the JSON Schema.

The 5 patterns

1. JSONL session record (one file per session, one line per event)

Every agent session produces a single append-only file: sessions/<sessionId>.jsonl. Every event is one JSON line. The line is never pretty-printed, never rewritten, never truncated. The file is closed with O_APPEND semantics, so a crash at line 47 leaves line 47 intact (the kernel flushes per write). The file is named after the sessionId so grep, jq, and awk all work without a custom decoder.

The session record is the single source of truth for the session. The agent runtime reads from it on resume (the long-term store is downstream). The cost attribution layer reads from it on rollup. The eval harness reads from it on regression. The redactor reads from it on PII scan. The SLO tracker reads from it on burn rate. One format, one file per session, one writer.

This is what the Agent Session Observability CLI reads: framework-agnostic JSONL session-record reader, per-session and per-agent rollups, degenerate-loop detection, pairs with the Agent Inflight Telemetry CLI (per-span capture), the Agent Turn Health Inspector CLI (per-turn health), and the Agent Trace Replay CLI (step-level diff). The runtime in this post is a 95-line compatible core that the CLI reads; the CLI adds the rollup, the degenerate-loop detector, and the CI-gate wrapper.

2. Schema-first with JSON Schema validation in CI

Every event validates against a versioned JSON Schema before it hits disk. The schema is the contract; the logger is the writer; the CI gate is the enforcer. If a refactor introduces a new event type, the schema bumps; the CI gate fails the PR that did not update the schema; the runtime refuses to write the un-schema-valid event.

The schema covers the eight event types and the cross-cutting fields (sessionId, turn, eventId, timestamp, tokenOffset, idempotencyKey). The tokens_in, tokens_out, model_id, and tool_call_count fields are required on the events that produce them (request_started, completed). The tool_name and tool_args_hash fields are required on tool_called. The decision and reason fields are required on context_evicted and budget_decided. A line that does not validate is not written. A line that does not write is not in the record.

The schema is the single artifact that the cost attribution layer, the eval harness, the SLO tracker, the test pyramid, and the idempotency layer all depend on. The 26th post on the testing pyramid argued that the contract tier asserts the schema is enforced. This post argues the schema is the first thing written, not the last thing retrofitted.

3. Eight-event taxonomy (the only verbs an agent can do)

An LLM agent does eight things. Every side effect, every decision, every state change maps to exactly one of them. The taxonomy is closed: if a new verb is needed, the schema bumps; if a verb is not in the taxonomy, the agent is doing something it should not be doing silently.

Eight events, no more, no fewer. The taxonomy is the contract that the schema enforces, the cost attribution layer aggregates over, the eval harness regresses against, and the Woodpecker CI gate audits. If a new event type is needed (a new state change the agent must make auditable), the taxonomy is extended and the schema bumps. The extension is a versioned, audited change, not a quiet refactor.

4. Write-time PII redaction (sha256-prefixed masks at write, not at read)

PII and secrets must never enter the session record in cleartext. The redactor runs at write time, not at read time. The redactor is a deterministic function: redact(s) -> sha256(s)[:8] + "_" + s.length + "_" + last4(s). The same input always produces the same mask. The mask preserves the length, the last 4 characters, and a content hash, so downstream cost attribution can still count token spend, the eval harness can still detect behavioral drift, and a human can still recognize the value without being able to reconstruct it.

The redactor covers 8 secret-shape patterns: sk- + 20+ chars (OpenAI), sk-ant- + 20+ chars (Anthropic), ghp_ + 30+ chars (GitHub PAT), AKIA + 16 chars (AWS), sk_live_ + 20+ chars (Stripe live), generic API_KEY=value / SECRET=value / TOKEN=value env-var shapes, 64-char hex (Ethereum private keys), and 12+ word BIP-39 mnemonics. The shapes are checked at write time, not at read time, because the redactor at read time is a post-hoc scrubber that has already leaked.

This is what the Agent Secrets Audit CLI does: post-hoc secret-leak auditor for AI agent session JSONL logs, scans every turn for the same 8 secret-shape patterns with severity 1-10, masked findings (first 4 + last 4 chars visible, middle *-filled) so secrets never land in reports. The runtime in this post is the write-time redactor that prevents the leak; the CLI is the post-hoc audit that catches what slipped through.

5. Line + turn + token_offset searchable index (every line is a primary key)

Every line in the session record carries four fields that make the record queryable in <100ms on a 1,000-event file: sessionId (which file), turn (which user turn), tokenOffset (where in the context the event sits), and a content-hash eventId (the line’s primary key, sha256 of the canonicalized JSON). A query like “show me the budget_decided events for session X that triggered an eviction” resolves in <100ms on a 1,000-event file because every line carries the indices, no separate index file is needed.

The tokenOffset is the running sum of tokens_in + tokens_out across all prior request_started and completed events in the session. It is the position in the context window the event sits at the moment it was written. A context_evicted event with tokenOffset: 47000 on a 64K-window model is a 73%-of-budget eviction; a context_evicted with tokenOffset: 12000 is an early compaction. The downstream debug session can answer “why did the budget blow out at turn 8?” with a single jq line.

The eventId is the primary key for the line. Two events with the same eventId are the same event (idempotency). Two events with different eventIds are different events (audit). The cost attribution layer dedupes by eventId; the eval harness regresses by eventId; the SLO tracker counts by eventId. The index is the line itself; the file is the database; the schema is the type system.

The 4 anti-patterns

Anti-pattern 1: Prettyprint the prompt (the agent eats the disk)

The agent’s debug logger is configured to dump the full system prompt (12K tokens), the full tool catalog (8K tokens), the full conversation history (24K tokens), and the full tool result (16K tokens) on every LLM call. The log file is 60K tokens per LLM call. The session runs 40 LLM calls. The log file is 2.4M tokens, or roughly 10MB of JSON. The session ran for 12 minutes. The disk filled at 2am on a Saturday. The agent is silently down for 6 hours before anyone notices.

Fix: pattern 2 (schema-first) + pattern 3 (eight-event taxonomy) + pattern 4 (write-time redaction). The schema explicitly rejects full-prompt dumps; the request_started event carries system_prompt_hash and tool_catalog_hash, not the full text. The redactor scrubs any cleartext that slips through. The session record is bounded by the schema, not by what the developer thought to log. A 40-call session produces a 200KB JSONL file, not a 10MB file, and the disk does not fill.

Anti-pattern 2: Log only the response (the tool-call trail is lost)

The framework’s default logger only sees the final LLM response. The 4 tool calls that produced the response are invisible to the logger. The user’s billing complaint says “I was charged $0.18 for one question.” The cost attribution layer cannot answer the question because the tool calls are not in the record. The eval harness cannot answer “did the agent take the right path?” because the path is not in the record. The SLO tracker cannot answer “what was the burn rate at turn 6?” because the per-call latency is not in the record.

Fix: pattern 3 (eight-event taxonomy) explicitly includes tool_called and tool_returned as first-class events. Every tool invocation is a structured line, with tool_name, tool_args_hash, idempotency_key, latency_ms, and result_hash. The cost attribution layer rolls up the tool calls; the eval harness traces the path; the SLO tracker counts the per-call latency. The response is one event of eight; it is not the only event.

Anti-pattern 3: JSON per call with no schema (the keys drift between versions)

The agent calls JSON.stringify({ts: Date.now(), tokens: llm.tokens, model: llm.model}) per LLM call. The keys are not typed. The refactor at v1.4 renames tokens to tokenIn and adds tokenOut. The cost attribution layer, written for v1.3, silently returns NaN for 12% of calls because llm.tokens is now undefined. The eval harness, written for v1.3, returns the same 12% of calls as “no behavior” because the input length is undefined. The SLO tracker, written for v1.3, returns 0ms p99 latency for the same 12% because the latency field is missing. The bug is invisible for 3 weeks until a finance-team alert fires on a $0 NaN.

Fix: pattern 2 (schema-first). The JSON Schema requires tokens_in, tokens_out, model_id, and tool_call_count on every request_started and completed event. A line that does not validate is not written. The refactor at v1.4 must update the schema; the CI gate fails the PR that did not; the runtime refuses to ship the un-schema-valid event. The cost attribution layer, the eval harness, and the SLO tracker all read the same schema, the same keys, the same types. Drift is impossible by construction.

Anti-pattern 4: Local file only, no rotation (the disk fills at 2am)

The agent writes to /var/log/agent.log with no rotation, no compression, no query path. The file grows without bound. The disk fills at 2am on a Saturday. The agent is silently down for 6 hours before anyone notices. The debug session the next morning starts with the words “I cannot reproduce this because the log file rotated three days ago” — except the file did not rotate, the disk filled, and the file is intact but the agent is not. The 3 most recent hours of session records are unrecoverable; the 2,400-line JSONL is unreadable because the agent is down.

Fix: pattern 1 (JSONL session record) + a rotation policy. One file per session, named sessions/<sessionId>.jsonl, closed when the session ends. The file is gzipped on close and shipped to the trace backend (or to local sessions/archive/ if no backend). New sessions open new files. The disk does not fill because every file has a bounded size (the session has a bounded duration). The 2am Saturday is a no-op; the disk usage is bounded by the number of concurrent sessions, not by the cumulative token spend.

The 95-line drop-in structured-logger runtime

Here is a reference implementation of the structured logger that exercises patterns 1, 2, 3, and 4. It is intentionally small enough to read in one sitting and intentionally complete enough to be the core of a production agent. The schema is a single constant, the redactor is a single function, the writer is a single function, and the eight-event taxonomy is the only thing the writer accepts.

// structured-logger.ts
// Drop-in TypeScript structured-logger runtime for LLM agents.
// Zero deps, zero network, deterministic. Pairs with the Agent Session
// Observability CLI and the Agent Secrets Audit CLI for the production
// readers; the runtime in this post is the writer.

import { createHash } from 'node:crypto';
import { appendFileSync, mkdirSync } from 'node:fs';
import { join } from 'node:path';

export type EventType =
  | 'request_started' | 'tool_called' | 'tool_returned'
  | 'context_evicted' | 'budget_decided' | 'compacted'
  | 'completed' | 'failed';

// Pattern 3: the closed taxonomy
export const TAXONOMY: readonly EventType[] = [
  'request_started', 'tool_called', 'tool_returned', 'context_evicted',
  'budget_decided', 'compacted', 'completed', 'failed',
];

export type Event = {
  eventId: string;        // sha256(canonical JSON), primary key
  sessionId: string;
  turn: number;
  tokenOffset: number;    // running sum of tokens at write time
  timestamp: string;      // ISO-8601
  type: EventType;
  idempotencyKey?: string;
  [k: string]: unknown;   // type-specific fields
};

// Pattern 4: write-time PII redactor (sha256-prefixed, length-preserving)
const SECRET_PATTERNS: RegExp[] = [
  /sk-[A-Za-z0-9_-]{20,}/g,             // OpenAI
  /sk-ant-[A-Za-z0-9_-]{20,}/g,         // Anthropic
  /ghp_[A-Za-z0-9]{30,}/g,              // GitHub PAT
  /AKIA[A-Z0-9]{16}/g,                  // AWS
  /sk_live_[A-Za-z0-9]{20,}/g,          // Stripe live
  /[A-Z_]*KEY=[A-Za-z0-9_-]{8,}/g,      // generic env-var KEY=
  /[A-Fa-f0-9]{64}/g,                   // 64-char hex (Ethereum privkey)
  /\b([a-z]+\s){11,24}[a-z]+\b/g,       // 12-24 word BIP-39 mnemonic
];

export const redact = (s: string): string => {
  let out = s;
  for (const pat of SECRET_PATTERNS) {
    out = out.replace(pat, (m) => {
      const h = createHash('sha256').update(m).digest('hex').slice(0, 8);
      const last4 = m.slice(-4);
      return `sha256:${h}_len${m.length}_...${last4}`;
    });
  }
  return out;
};

const canonicalize = (e: Event): string =>
  JSON.stringify(e, Object.keys(e).sort());

const eventId = (e: Event): string =>
  createHash('sha256').update(canonicalize(e)).digest('hex');

// Pattern 2: schema-first validation (minimal — production uses ajv + JSON Schema)
const REQUIRED_BASE = ['eventId', 'sessionId', 'turn', 'tokenOffset', 'timestamp', 'type'];
const validate = (e: Event): string | null => {
  for (const k of REQUIRED_BASE) {
    if (e[k] === undefined || e[k] === null) return `missing required field: ${k}`;
  }
  if (!TAXONOMY.includes(e.type)) return `event type not in taxonomy: ${e.type}`;
  return null;
};

// Pattern 1 + 5: append-only JSONL writer, one file per session
export class StructuredLogger {
  private path: string;
  private tokenOffset = 0;

  constructor(sessionId: string, dir = './sessions') {
    mkdirSync(dir, { recursive: true });
    this.path = join(dir, `${sessionId}.jsonl`);
  }

  // Caller passes the event with all required fields. The redactor runs on
  // the serialized JSON before write. The tokenOffset is updated after write.
  write(partial: Omit<Event, 'eventId' | 'timestamp' | 'tokenOffset'> &
                  { deltaTokensIn?: number; deltaTokensOut?: number }): Event {
    const e: Event = {
      ...partial,
      eventId: '',  // filled below
      timestamp: new Date().toISOString(),
      tokenOffset: this.tokenOffset,
    };
    e.eventId = eventId(e);
    const err = validate(e);
    if (err) throw new Error(`schema validation failed: ${err}`);
    const redacted = JSON.parse(redact(JSON.stringify(e)));
    appendFileSync(this.path, JSON.stringify(redacted) + '\n');
    this.tokenOffset += (partial.deltaTokensIn ?? 0) + (partial.deltaTokensOut ?? 0);
    return e;
  }
}

// --- 8 selftest cases (run with: npx tsx structured-logger.ts) ---
const selfTest = () => {
  const log = new StructuredLogger('test-session-001');
  let n = 0, ok = 0;
  const t = (name: string, cond: boolean) => { n++; if (cond) ok++; else console.error('FAIL', name); };

  // 1. request_started
  const r1 = log.write({ sessionId: 'test-session-001', turn: 1, type: 'request_started',
    model_id: 'claude-sonnet-4', system_prompt_hash: 'sha256:abc', tool_catalog_hash: 'sha256:def',
    tokens_in: 1200, deltaTokensIn: 1200 });
  t('request_started validates', r1.eventId.length === 64);

  // 2. tool_called
  const t1 = log.write({ sessionId: 'test-session-001', turn: 1, type: 'tool_called',
    tool_name: 'web_search', tool_args_hash: 'sha256:ghi', idempotency_key: 'idem-001', deadline_ms: 5000 });
  t('tool_called validates', t1.eventId.length === 64);

  // 3. tool_returned
  const t2 = log.write({ sessionId: 'test-session-001', turn: 1, type: 'tool_returned',
    tool_name: 'web_search', status: 'ok', latency_ms: 1230, result_hash: 'sha256:jkl' });
  t('tool_returned validates', t2.eventId.length === 64);

  // 4. context_evicted
  log.write({ sessionId: 'test-session-001', turn: 1, type: 'context_evicted',
    decision: 'evict_first', evicted_blocks: ['turn-0-tool-trace'], kept_blocks: ['system', 'user'],
    plan_hash: 'sha256:mno', budget_before: 48000, budget_after: 32000 });

  // 5. budget_decided
  log.write({ sessionId: 'test-session-001', turn: 1, type: 'budget_decided',
    planned_in: 4000, planned_out: 1500, ceiling: 64000, headroom: 58500, overflow: false, plan: 'ok' });

  // 6. compacted
  log.write({ sessionId: 'test-session-001', turn: 1, type: 'compacted',
    summary_hash: 'sha256:pqr', intent_vector: { goal: 'summarize' }, dropped_blocks: ['turn-0-msg'], kept_blocks: ['intent'] });

  // 7. completed
  const c = log.write({ sessionId: 'test-session-001', turn: 1, type: 'completed',
    total_tokens_in: 1200, total_tokens_out: 800, total_tool_calls: 1, total_latency_ms: 1230, answer_hash: 'sha256:stu',
    deltaTokensOut: 800 });
  t('completed validates', c.eventId.length === 64);

  // 8. failed + redaction check
  const redacted = redact('my openai key is sk-abcdefghijklmnopqrstuvwxyz and my github is ghp_abcdefghijklmnopqrstuvwxyz1234567890');
  t('redact masks OpenAI key', !redacted.includes('sk-abcdefghijklmnopqrstuvwxyz') && redacted.includes('sha256:'));
  t('redact masks GitHub PAT', !redacted.includes('ghp_abcdefghijklmnopqrstuvwxyz1234567890') && redacted.includes('sha256:'));
  t('idempotency: same event -> same eventId', eventId({ ...r1, eventId: '', timestamp: r1.timestamp }) === r1.eventId);
  t('taxonomy: unknown type rejected', validate({ ...r1, type: 'foo' as EventType, eventId: 'x' }) !== null);
  t('schema: missing sessionId rejected', validate({ ...r1, sessionId: '', eventId: 'x' }) !== null);

  console.log(`selftest: ${ok}/${n} passed`);
  if (ok !== n) process.exit(1);
};
if (process.argv[1]?.endsWith('structured-logger.ts')) selfTest();

The Woodpecker CI gate

The CI gate asserts the eight-event taxonomy is closed (no new event types slipped in), every event in the fixture validates against the schema, the redactor masks every one of the 8 secret shapes, and the session-record writer is append-only. The gate is 5 audit scripts that run on every PR that touches agent-runtime/, structured-logger.ts, or any file that imports the logger.

# .woodpecker/structured-logging-gate.yml
# Woodpecker CI gate for the structured-logging contract.
# Runs on every PR that touches agent runtime or logger files.
# Fails the PR if any of the 5 audits fail.

steps:
  - name: taxonomy-closed
    image: node:20-alpine
    commands:
      - node -e "const t=require('./structured-logger.ts').TAXONOMY; \
        if(t.length!==8)process.exit(1); \
        for(const v of t)if(typeof v!=='string')process.exit(1);"

  - name: schema-validation
    image: node:20-alpine
    commands:
      - npx tsx test/structured-logger.schema.test.ts
      # Asserts every event in fixtures/agent-sessions/ validates.

  - name: redactor-covers-8-shapes
    image: node:20-alpine
    commands:
      - npx tsx test/structured-logger.redactor.test.ts
      # Asserts sk-, sk-ant-, ghp_, AKIA, sk_live_, KEY=, 64hex, BIP-39 all masked.

  - name: writer-append-only
    image: node:20-alpine
    commands:
      - grep -rn "appendFileSync\|writeFileSync\|createWriteStream" agent-runtime/ src/ | grep -v "appendFileSync"
      # Fails the PR if a non-append write to a session file is found.

  - name: fixture-roundtrip
    image: node:20-alpine
    commands:
      - npx tsx test/structured-logger.roundtrip.test.ts
      # Reads back a written session, asserts every line is valid JSON
      # and every line validates against the schema.

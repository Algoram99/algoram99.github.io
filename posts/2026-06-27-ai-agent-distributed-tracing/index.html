AI Agent Distributed Tracing:
6 Patterns, 5 Anti-Patterns, and a Drop-In Trace Collector

An AI agent that calls 4 tools, makes 2 API requests, and runs 3 reasoning steps creates 9+ spans. Without distributed tracing, those spans are orphans — disconnected events with no parent-child relationship, no causal chain, and no way to answer “why did this request take 12 seconds?”

𘉋️ TL;DR

Distributed tracing for AI agents means propagating a trace ID across every tool call, API boundary, and reasoning step so you can reconstruct the full causal chain of a request. This post covers 6 patterns (span context propagation, trace ID injection, causal chain correlation, adaptive sampling, latency budget enforcement, and OTLP export) and 5 anti-patterns that break correlation or leak data. The 130-line runtime at the bottom gives you all six patterns in one file.

The Problem: Orphan Spans

A typical agent request flows through these stages:

User message
  ☛ LLM call (2.1s)
    ☛ Tool: search_database (0.8s)
    ☛ Tool: call_external_api (1.5s)
      ☛ Retry on 429 (0.3s)
    ☛ LLM call: process results (1.8s)
  ☛ Response sent (6.2s total)

If each of those steps logs independently with its own request ID, you get 6 disconnected log entries. You can guess they're related by timestamps, but you can't prove the causal chain. Distributed tracing fixes this by propagating a traceId and spanId through every hop.

Without TracingWith Distributed Tracing
“Something took 6 seconds”“call_external_api took 1.5s, including a 0.3s retry”
Manual timestamp correlationParent-child span tree with microsecond precision

Pattern 1: Span Context Propagation Across Tool Calls

Every tool call must carry the current span context forward. The span context is a small struct: traceId, spanId, and traceFlags. Without it, the tool's execution is an orphan — you know what happened but not why or in service of which request.

✅ Pattern: Propagate Span Context

// Carry trace context into every tool call
interface SpanContext {
  traceId: string;    // 32-char hex, shared across entire request
  spanId: string;     // 16-char hex, unique per span
  parentSpanId: string | null;  // links to the calling span
  traceFlags: number; // sampling bit
}

function callTool<T>(
  toolName: string,
  fn: (ctx: SpanContext) => Promise<T>,
  parentCtx: SpanContext
): Promise<T> {
  // Create a child span under the parent
  const childCtx: SpanContext = {
    traceId: parentCtx.traceId,        // SAME trace
    spanId: generateSpanId(),          // NEW span
    parentSpanId: parentCtx.spanId,    // LINK to parent
    traceFlags: parentCtx.traceFlags,
  };

  const span = tracer.startSpan(toolName, {
    childOf: parentCtx,
    attributes: { 'tool.name': toolName },
  });

  return fn(childCtx)
    .then(result => {
      span.setStatus({ code: 1 }); // OK
      span.end();
      return result;
    })
    .catch(err => {
      span.setStatus({ code: 2, message: err.message }); // ERROR
      span.recordException(err);
      span.end();
      throw err;
    });
}

The childCtx carries the same traceId but a new spanId with the parent's spanId as a link. This is the fundamental invariant of distributed tracing.

Pattern 2: Trace ID Injection Into LLM Prompts

Injecting the trace ID into the system prompt lets the LLM self-report which trace it is processing. This is critical for debugging: when the model says “I searched for X”, you can look up the exact tool-call span by trace ID.

✅ Pattern: Inject Trace Metadata

// Inject trace context into the system prompt
function buildTracedSystemPrompt(
  basePrompt: string,
  ctx: SpanContext
): string {
  return `${basePrompt}

<!-- trace: ${ctx.traceId} span: ${ctx.spanId} -->
You are processing request under trace ${ctx.traceId}.
When you call tools, include this trace ID in metadata.`;
}

// Extract trace ID from model output for correlation
function extractTraceFromOutput(
  output: string,
  expectedTraceId: string
): boolean {
  const match = output.match(/trace:\s*([a-f0-9]{32})/);
  if (match && match[1] === expectedTraceId) {
    return true; // Model correctly propagated the trace
  }
  return false; // Orphan output — investigate

This pattern is unique to LLM agents: traditional microservices propagate context via HTTP headers. Agents propagate context via prompt injection (the good kind).

Pattern 3: Distributed Span Correlation by Causal Chain

Parent-child span IDs create a tree, but agent workflows are often DAGs (directed acyclic graphs) — a span may have multiple parents (e.g., a tool call triggered by a retry). Use links to represent non-tree causal relationships.

✅ Pattern: Causal Links for DAG Workflows

// Link spans across retry/fan-out boundaries
interface Span {
  traceId: string;
  spanId: string;
  parentSpanId: string | null;
  links: Array<{ traceId: string; spanId: string; attrs?: Record<string, string> }>;
}

// When a retry spawns a new attempt, LINK it to the original
function retryWithTrace<T>(
  fn: (ctx: SpanContext) => Promise<T>,
  originalCtx: SpanContext,
  attempt: number
): Promise<T> {
  const retryCtx = createChildSpan(originalCtx);
  const span = tracer.startSpan(`retry-attempt-${attempt}`, {
    childOf: originalCtx,
    links: [{
      traceId: originalCtx.traceId,
      spanId: originalCtx.spanId,
      attrs: { 'retry.reason': 'timeout', 'retry.attempt': String(attempt) },
    }],
  });
  return fn(retryCtx).finally(() => span.end());
}

Links let you answer “was this span caused by a retry or a fresh request?” without ambiguity. Jaeger and Tempo both render links as dashed edges in the trace graph.

Pattern 4: Sampling Strategies for High-Volume Agent Traces

An agent handling 10,000 requests/day with 9 spans each produces 90,000 spans/day. At 100% sampling, that's 2.7M spans/month — most of which are identical “happy path” traces. Use adaptive sampling: sample 100% of errors, 10% of slow requests, and 1% of fast-success requests.

✅ Pattern: Adaptive Sampling by Outcome

// Sample based on outcome, not just random probability
function shouldSample(span: Span): boolean {
  // Always sample errors
  if (span.status?.code === 2) return true;

  // Always sample slow requests (> 5s)
  const durationMs = span.endTime - span.startTime;
  if (durationMs > 5000) return true;

  // Always sample retries (links indicate retry)
  if (span.links && span.links.length > 0) return true;

  // Sample 10% of slow-ish requests (2-5s)
  if (durationMs > 2000) return Math.random() < 0.10;

  // Sample 1% of fast-success
  return Math.random() < 0.01;
}

// Tail-based sampling: decide AFTER the span completes
function tailSample(trace: Span[]): boolean {
  const hasError = trace.some(s => s.status?.code === 2);
  const hasRetry = trace.some(s => s.links?.length > 0);
  const totalMs = Math.max(...trace.map(s => s.endTime))
                - Math.min(...trace.map(s => s.startTime));

  if (hasError || hasRetry) return true;
  if (totalMs > 5000) return true;
  return Math.random() < 0.05; // 5% of healthy traces

Tail-based sampling is strictly better than head-based for agent traces because you decide after seeing the outcome. You never miss an error trace.

Pattern 5: Trace-Based Latency Budget Enforcement

Define a latency budget for each request type. If the cumulative span time exceeds the budget, fail early instead of letting the agent spiral into a 30-second timeout.

✅ Pattern: Enforce a Per-Request Latency Budget

// Fail fast when cumulative span time exceeds budget
class LatencyBudget {
  private spent = 0;
  constructor(private readonly budgetMs: number) {}

  consume(spanMs: number): void {
    this.spent += spanMs;
    if (this.spent > this.budgetMs) {
      throw new LatencyBudgetExceeded(
        `Budget exceeded: ${this.spent}ms > ${this.budgetMs}ms`
      );
    }
  }

  remaining(): number {
    return Math.max(0, this.budgetMs - this.spent);
  }
}

// Wire it into your agent loop
async function runAgentWithBudget(
  messages: Message[],
  budgetMs: number
): Promise<Response> {
  const budget = new LatencyBudget(budgetMs);

  for (const step of agentSteps) {
    const start = Date.now();
    const result = await step.execute();
    budget.consume(Date.now() - start);

    if (budget.remaining() < step.estimatedCostMs) {
      return { truncated: true, reason: 'latency_budget', result };
    }
  }
  return { truncated: false, result: finalResult };
}

This pattern turns “the agent is slow” from a vague complaint into a budget enforcement problem. You know exactly which span consumed the budget and can set SLOs on it.

Pattern 6: Trace Export to OTLP-Compatible Backends

Export traces using the OpenTelemetry Protocol (OTLP). This works with Jaeger, Tempo, Honeycomb, Datadog, and any OTLP-compatible backend. Don't build a custom trace format — you'll regret it when you need to switch backends.

✅ Pattern: OTLP Export with Redaction

// Export traces via OTLP with prompt content redacted
function exportTraces(
  spans: Span[],
  endpoint: string // e.g., http://localhost:4318/v1/traces
): Promise<void> {
  const otlpSpans = spans.map(s => ({
    traceId: s.traceId,
    spanId: s.spanId,
    parentSpanId: s.parentSpanId,
    name: s.name,
    startTimeUnixNano: String(s.startTime * 1e6),
    endTimeUnixNano: String(s.endTime * 1e6),
    status: s.status,
    attributes: redactSensitiveAttrs(s.attributes),
    links: s.links?.map(l => ({
      traceId: l.traceId,
      spanId: l.spanId,
      attributes: l.attrs,
    })),
  }));

  return fetch(endpoint, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ resourceSpans: [{ scopeSpans: [{ spans: otlpSpans }] }] }),
  }).then(r => {
    if (!r.ok) console.error(`OTLP export failed: ${r.status}`);
  });
}

function redactSensitiveAttrs(
  attrs: Record<string, string>
): Record<string, string> {
  const REDACT_KEYS = ['prompt', 'completion', 'user_input',
                       'system_prompt', 'tool_input', 'tool_output'];
  const redacted: Record<string, string> = {};
  for (const [key, value] of Object.entries(attrs)) {
    redacted[key] = REDACT_KEYS.some(rk => key.includes(rk))
      ? `[REDACTED:${value.length}chars]`
      : value;
  }
  return redacted;
}

Critical: always redact prompt, completion, tool_input, and tool_output before exporting. These fields may contain user data, API keys, or PII that should never reach your observability backend.

5 Anti-Patterns (and How to Fix Them)

❌ Anti-Pattern 1: Missing Span Context on Tool Calls

Symptom: Tool calls appear as standalone traces with no parent. You can see that a database query happened but not which request triggered it.

Fix: Every tool call must receive and propagate the parent SpanContext. Pass it as an explicit parameter — don't rely on global state or ambient context (those break in async/concurrent agent loops).

❌ Anti-Pattern 2: Trace ID as Random UUID Per Request

Symptom: Each component generates its own UUID. Cross-service correlation is impossible because no two components share a trace ID.

Fix: Generate the trace ID once at the request entry point and propagate it via SpanContext. Use the W3C Trace Context format (32-char hex). Never let downstream components generate their own trace IDs.

❌ Anti-Pattern 3: No Correlation Between Agent Steps

Symptom: Each LLM call, tool call, and reasoning step logs independently. You see 9 spans but they form no tree — they're a flat list with no parent-child links.

Fix: Use parentSpanId on every child span. The first LLM call is the root span; every tool call it triggers is a child. Reasoning steps are children of the LLM call that produced them. Build the tree explicitly.

❌ Anti-Pattern 4: 100% Sampling on Production Traffic

Symptom: Your tracing backend costs $2,000/month because you're storing 2.7M spans. Worse, the interesting traces (errors, retries, slow requests) are buried in a sea of identical happy-path traces.

Fix: Use tail-based sampling. Sample 100% of errors and retries, 10% of slow requests, and 1% of fast-success. This cuts volume by 95% while keeping 100% of the traces you actually debug.

❌ Anti-Pattern 5: Exporting Traces Without Redacting Prompt Content

Symptom: User prompts, which may contain PII, API keys, or sensitive business data, appear in your Jaeger/Honeycomb/Datadog dashboard. Anyone with observability access can read user conversations.

Fix: Redact prompt, completion, tool_input, and tool_output attributes before export. Replace with [REDACTED:Nchars] to preserve length metadata for debugging without leaking content.

The 130-Line Distributed Trace Collector

Here's a complete, drop-in trace collector that implements all six patterns. Zero dependencies beyond Node.js 20+. It handles span context propagation, causal chain correlation, adaptive sampling, latency budget enforcement, and OTLP export with redaction.

// distributed-trace-collector.ts
// 130-line distributed tracing runtime for AI agents.
// Patterns 1-6 in one file. Zero deps. Node 20+.

import { randomBytes } from 'crypto';

// --- Types ---
interface SpanContext {
  traceId: string;
  spanId: string;
  parentSpanId: string | null;
  traceFlags: number;
}

interface Span extends SpanContext {
  name: string;
  startTime: number;
  endTime: number;
  status: { code: number; message?: string };
  attributes: Record<string, string>;
  links: Array<{ traceId: string; spanId: string; attrs?: Record<string, string> }>;
  events: Array<{ name: string; timestamp: number; attrs?: Record<string, string> }>;
}

// --- Span ID generation (W3C format: 16-char hex) ---
function genSpanId(): string {
  return randomBytes(8).toString('hex');
}

// --- Trace ID generation (W3C format: 32-char hex) ---
function genTraceId(): string {
  return randomBytes(16).toString('hex');
}

// --- Trace Collector ---
class TraceCollector {
  private spans: Span[] = [];
  private sampler: (span: Span) => boolean;
  private exporter: (spans: Span[]) => Promise<void>;
  private budgetMs: number;
  private spentMs = 0;

  constructor(opts: {
    sampler?: (s: Span) => boolean;
    exporter?: (s: Span[]) => Promise<void>;
    budgetMs?: number;
  } = {}) {
    this.sampler = opts.sampler ?? defaultSampler;
    this.exporter = opts.exporter ?? ((s) => Promise.resolve());
    this.budgetMs = opts.budgetMs ?? 10000;
  }

  // Pattern 1: Start a span with parent context propagation
  startSpan(
    name: string,
    parentCtx: SpanContext | null,
    attrs: Record<string, string> = {}
  ): { span: Span; ctx: SpanContext } {
    const ctx: SpanContext = parentCtx
      ? {
          traceId: parentCtx.traceId,
          spanId: genSpanId(),
          parentSpanId: parentCtx.spanId,
          traceFlags: parentCtx.traceFlags,
        }
      : {
          traceId: genTraceId(),
          spanId: genSpanId(),
          parentSpanId: null,
          traceFlags: 1,
        };

    const span: Span = {
      ...ctx,
      name,
      startTime: Date.now(),
      endTime: 0,
      status: { code: 0 },
      attributes: { ...attrs, 'agent.span_name': name },
      links: [],
      events: [],
    };

    return { span, ctx };
  }

  // Pattern 3: Add causal links (for retries, fan-out)
  addLink(span: Span, targetCtx: SpanContext, attrs?: Record<string, string>): void {
    span.links.push({
      traceId: targetCtx.traceId,
      spanId: targetCtx.spanId,
      attrs,
    });
  }

  // Pattern 5: Consume latency budget
  consumeBudget(ms: number): void {
    this.spentMs += ms;
    if (this.spentMs > this.budgetMs) {
      throw new Error(`LatencyBudgetExceeded: ${this.spentMs}ms > ${this.budgetMs}ms`);
    }
  }

  remainingBudget(): number {
    return Math.max(0, this.budgetMs - this.spentMs);
  }

  // End a span and record it
  endSpan(span: Span, status: { code: number; message?: string } = { code: 1 }): void {
    span.endTime = Date.now();
    span.status = status;

    // Pattern 4: Adaptive sampling — decide AFTER span completes
    if (this.sampler(span)) {
      this.spans.push(span);
    }

    // Consume budget
    const duration = span.endTime - span.startTime;
    this.consumeBudget(duration);
  }

  // Pattern 6: Export to OTLP with redaction
  async flush(endpoint: string): Promise<void> {
    if (this.spans.length === 0) return;
    const redacted = this.spans.map(s => ({
      ...s,
      attributes: redactAttrs(s.attributes),
    }));
    await this.exporter(redacted);
    await exportOTLP(redacted, endpoint);
    this.spans = [];
  }

  // Get all recorded spans (for debugging)
  getSpans(): ReadonlyArray<Span> {
    return this.spans;
  }
}

// --- Default adaptive sampler (Pattern 4) ---
function defaultSampler(span: Span): boolean {
  if (span.status.code === 2) return true;           // errors
  if (span.links.length > 0) return true;             // retries
  const durMs = span.endTime - span.startTime;
  if (durMs > 5000) return true;                       // slow
  if (durMs > 2000) return Math.random() < 0.10;
  return Math.random() < 0.01;
}

// --- Redaction (Pattern 6 safety) ---
function redactAttrs(attrs: Record<string, string>): Record<string, string> {
  const REDACT = ['prompt', 'completion', 'user_input', 'system_prompt',
                  'tool_input', 'tool_output', 'message'];
  const out: Record<string, string> = {};
  for (const [k, v] of Object.entries(attrs)) {
    out[k] = REDACT.some(r => k.toLowerCase().includes(r))
      ? `[REDACTED:${v.length}chars]`
      : v;
  }
  return out;
}

// --- OTLP HTTP export ---
async function exportOTLP(spans: Span[], endpoint: string): Promise<void> {
  const body = JSON.stringify({
    resourceSpans: [{
      scopeSpans: [{
        spans: spans.map(s => ({
          traceId: s.traceId,
          spanId: s.spanId,
          parentSpanId: s.parentSpanId,
          name: s.name,
          startTimeUnixNano: String(s.startTime * 1e6),
          endTimeUnixNano: String(s.endTime * 1e6),
          status: s.status,
          attributes: Object.entries(s.attributes).map(([k, v]) =>
            ({ key: k, value: { stringValue: v } })),
          links: s.links.map(l => ({
            traceId: l.traceId, spanId: l.spanId,
            attributes: l.attrs ? Object.entries(l.attrs).map(([k, v]) =>
              ({ key: k, value: { stringValue: v } })) : [],
          })),
        })),
      }],
    }],
  });
  try {
    const res = await fetch(endpoint, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body,
    });
    if (!res.ok) console.error(`OTLP export failed: ${res.status}`);
  } catch (e) {
    console.error(`OTLP export error: ${(e as Error).message}`);
  }
}

export { TraceCollector, SpanContext, Span };

Woodpecker CI Gate

Add this to your CI pipeline to catch tracing regressions before they reach production:

# .woodpecker.yml
steps:
  trace-coverage-check:
    image: node:20-alpine
    commands:
      - |
        node -e '
        const fs = require("fs");
        const path = require("path");

        // Ensure every tool call propagates span context
        const srcDir = "./src/tools";
        if (!fs.existsSync(srcDir)) {
          console.log("SKIP: no tools directory");
          process.exit(0);
        }

        const files = fs.readdirSync(srcDir).filter(f => f.endsWith(".ts"));
        let violations = 0;

        for (const file of files) {
          const content = fs.readFileSync(path.join(srcDir, file), "utf8");

          // Check for span context parameter
          if (content.includes("async function") &&
              !content.includes("ctx") &&
              !content.includes("SpanContext")) {
            console.error(`FAIL: ${file} has async functions without SpanContext`);
            violations++;
          }

          // Check for trace ID propagation
          if (content.includes("callTool") &&
              !content.includes("traceId")) {
            console.error(`FAIL: ${file} calls tools without trace propagation`);
            violations++;
          }
        }

        if (violations > 0) {
          console.error(`\n${violations} tracing violation(s) found`);
          process.exit(1);
        }
        console.log("OK: all tools propagate span context");
        '

Conclusion

Distributed tracing is the difference between debugging an agent and guessing at an agent. Without it, you have a pile of logs with timestamps and hope. With it, you have a causal tree that shows exactly which tool call, API request, or retry consumed the latency budget.

The patterns in this post work because they enforce causal continuity: every span links to its parent, every trace carries a stable ID, and every export is redacted. The anti-patterns fail because they break this continuity — orphan spans, disconnected traces, or leaked user data.

Start with Pattern 1 (span context propagation). It's the 80/20 win. Then add Pattern 4 (adaptive sampling) to control costs, and Pattern 5 (latency budget) to enforce SLOs. The full runtime above gives you all six patterns in one file.

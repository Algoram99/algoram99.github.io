How to Implement a Circuit Breaker for LLM API Calls

An HTTP circuit breaker is not enough. LLM APIs stream tokens, charge by the token, and trip on 429 storms in seconds. A circuit breaker for an LLM call has to detect six failure modes (not one), cancel in-flight streams when it opens, and probe the API back to health with a token-bounded request — not a ping. This post walks through a 110-line reference TypeScript implementation, the 4 anti-patterns that silently leave you paying for half-rendered completions during outages, and a chaos-test harness that kills the API mid-stream to prove the breaker actually trips.

TL;DR

An LLM-aware circuit breaker must detect 6 signals (HTTP 429, 5xx, p95 latency, per-window USD cost, streaming-token-stall, in-flight queue depth), maintain a 3-state machine (CLOSED / OPEN / HALF_OPEN) that the HTTP-default pattern does not generalize to, and cancel in-flight streams the moment it opens — not after they finish. The reference implementation below is 110 lines of TypeScript: zero dependencies, zero retries-by-default, drop-in for any OpenAI/Anthropic/Gemini-style fetch call, and configurable for cost-cap and latency-cap trips.

It pairs with the Agent Inflight Telemetry CLI Agent Ingress Firewall CLI 9-step LLM cost reduction guide that covers the rest of the cost-saving loop. The chaos-test harness at the end runs against a local stub server and verifies the breaker opens within 3 failures, recovers within 1 probe, and never lets a single open-state request through.

Why HTTP-default circuit breakers fail for LLM APIs

You have probably read the Martin Fowler circuit-breaker essay. The pattern is clean: count failures, open at a threshold, half-open after a cooldown, close on a probe success. The Hystrix / resilience4j / opossum libraries implement exactly that and ship it for HTTP microservices. Two things go wrong when you drop that exact pattern in front of an LLM API:

  1. LLM APIs stream. A 5xx that arrives 200ms into a 30-second completion does not “fail” the call the way a JSON 500 response fails a 50ms REST request. The breaker needs to count stream failures as failures, and it needs to cancel the stream when the breaker opens — not just refuse new ones. The HTTP-default breaker does neither.
  2. LLM APIs charge by the token. A successful completion that costs $0.80 is not a success. A “successful” 200 response that delivered 47,000 tokens of rephrased boilerplate is a cost regression, not a healthy call. The breaker needs a per-window USD trip threshold in addition to the per-call HTTP trip thresholds. The HTTP-default breaker has no concept of cost.

What you need is a LLM-aware breaker: same three states, same state-transition rules, but with six detector signals, a streaming-cancel hook, and a cost-budget window. The reference implementation below is the smallest version of that I have shipped across production agents. It is intentionally one file, zero dependencies, and copy-pasteable into any Node/TypeScript LLM runtime.

The 6-signal LLM detector

Every circuit breaker is a detector plus a state machine. The detector decides “is the upstream healthy right now?”. The state machine decides “given the recent detector verdicts, should I let the next call through, block it, or send a probe?”. For LLM APIs, the detector has six signals, not one:

SignalWhat it measuresDefault tripFailure mode it catches
HTTP 429Rate-limit response from the provider≥ 3 in 60sAccount-level rate limit, burst overage
HTTP 5xxProvider-side server error≥ 2 in 60sOutage, model-server crash
p95 latencyRolling 60s p95 of stream-first-byte time> 3× baselineProvider degraded, queueing delay, partial outage
Per-window USDTokens × price accumulated in 60s> configured costCapUsdRunaway agent loop, prompt-cache miss, verbose rephrasing
Stream-token stallNo token received in stallMsFirst stall onlyHung stream, broken keep-alive, partial response
Queue depthIn-flight requests vs. configured maxConcurrentExceeds limitMemory pressure, downstream backpressure ignored

The first two are familiar from any HTTP breaker. The third — p95 latency — is the signal most teams forget. A 429 storm often precedes the 429s by 30-60 seconds: the provider’s queue fills, latency creeps, and the breaker should open on the latency signal before the 429s start arriving. The fourth — per-window USD — is the signal that has to exist for the breaker to be a cost circuit as well as a reliability circuit. The fifth — stream-token stall — is unique to streaming. The sixth — queue depth — is the backpressure valve.

All six are evaluated at call-begin (for queue depth and rate) and at stream-end (for latency, cost, and stall). The detector returns a single verdict per call: OK, TRIP, or STALL. The state machine consumes the verdict.

Reference implementation: 110 lines of TypeScript

The implementation is a single file. There is no retry loop, no exponential backoff, no rate-limit handler — those are separate concerns. The breaker’s only job is to decide should this call go through right now, and to cancel in-flight streams the moment the state transitions to OPEN.

// lib/llm-circuit-breaker.ts
// Zero-dep LLM-aware circuit breaker. Drop-in for fetch() or stream-based
// OpenAI/Anthropic/Gemini clients. Released under MIT.

export type State = "CLOSED" | "OPEN" | "HALF_OPEN";

export interface BreakerConfig {
  windowMs: number;          // 60_000
  failureThreshold: number;  // 3
  costCapUsd: number;        // 5.00
  p95BaselineMs: number;     // 1500
  stallMs: number;           // 8000
  maxConcurrent: number;     // 16
  openCooldownMs: number;    // 30_000
  pricePer1kIn: number;      // 0.003
  pricePer1kOut: number;     // 0.015
}

export interface CallVerdict { ok: boolean; reason?: string; }

export class LlmCircuitBreaker {
  state: State = "CLOSED";
  private failures: number[] = [];        // ms timestamps
  private costWindow: { ts: number; usd: number }[] = [];
  private latencies: number[] = [];
  private inFlight = 0;
  private openAt = 0;
  private probeInFlight = false;
  private aborted: AbortController[] = [];
  constructor(private cfg: BreakerConfig) {}

  async precheck(): Promise {
    if (this.state === "OPEN") {
      if (Date.now() - this.openAt < this.cfg.openCooldownMs) {
        return { ok: false, reason: "OPEN" };
      }
      this.state = "HALF_OPEN";
      this.probeInFlight = false;
    }
    if (this.state === "HALF_OPEN" && this.probeInFlight) {
      return { ok: false, reason: "HALF_OPEN_BUSY" };
    }
    if (this.inFlight >= this.cfg.maxConcurrent) {
      return { ok: false, reason: "QUEUE_FULL" };
    }
    if (this.costWindowUsd() > this.cfg.costCapUsd) {
      this.trip("COST_CAP");
      return { ok: false, reason: "COST_CAP" };
    }
    this.inFlight++;
    if (this.state === "HALF_OPEN") this.probeInFlight = true;
    return { ok: true };
  }

  recordFailure(reason: string): void {
    this.failures.push(Date.now());
    this.pruneFailures();
    this.inFlight = Math.max(0, this.inFlight - 1);
    if (this.state === "HALF_OPEN") { this.trip(reason); return; }
    if (this.failures.length >= this.cfg.failureThreshold) this.trip(reason);
  }

  recordSuccess(latencyMs: number, inputTokens: number, outputTokens: number): void {
    this.latencies.push(latencyMs); this.pruneLatencies();
    const usd = (inputTokens / 1000) * this.cfg.pricePer1kIn
              + (outputTokens / 1000) * this.cfg.pricePer1kOut;
    this.costWindow.push({ ts: Date.now(), usd });
    this.pruneCost();
    this.inFlight = Math.max(0, this.inFlight - 1);
    this.failures = this.failures.filter(t => Date.now() - t < this.cfg.windowMs);
    if (this.state === "HALF_OPEN") { this.state = "CLOSED"; this.probeInFlight = false; }
    if (this.p95Latency() > this.cfg.p95BaselineMs * 3) this.trip("LATENCY_P95");
  }

  abortInFlight(): void {
    for (const ac of this.aborted) { try { ac.abort(); } catch {} }
    this.aborted = [];
  }

  private trip(reason: string): void {
    if (this.state === "OPEN") return;
    this.state = "OPEN";
    this.openAt = Date.now();
    this.abortInFlight();
  }
  // ... prune* and p95 helpers omitted for brevity
}

Three things to notice in the implementation above. First, the precheck() method is the only call site — the breaker is a guard, not a wrapper. The caller decides what to do with the {ok:false, reason} verdict (return a 503, return a cached fallback, route to a backup model). Second, abortInFlight() is the streaming-cancel hook: every AbortController the breaker handed out is aborted the instant the state flips to OPEN. Third, the cost-cap check happens in precheck() on every call, so the breaker trips on the next call after the per-window USD cap is exceeded, not on the call that already pushed it over.

Wiring it into an OpenAI streaming call

The reference client below shows the four-line integration. The breaker hands out an AbortController; the OpenAI client receives it; on trip, the breaker aborts and the client throws a DOMException: The operation was aborted, which the caller catches and turns into a 503.

// lib/llm-client.ts
import OpenAI from "openai";
import { LlmCircuitBreaker } from "./llm-circuit-breaker.js";

const breaker = new LlmCircuitBreaker({
  windowMs: 60_000, failureThreshold: 3, costCapUsd: 5.00,
  p95BaselineMs: 1500, stallMs: 8000, maxConcurrent: 16,
  openCooldownMs: 30_000, pricePer1kIn: 0.003, pricePer1kOut: 0.015,
});
const openai = new OpenAI();

export async function streamChat(prompt: string) {
  const verdict = await breaker.precheck();
  if (!verdict.ok) throw new Error("breaker_open:" + verdict.reason);
  const ac = new AbortController();
  breaker.aborted.push(ac);
  try {
    const stream = await openai.chat.completions.create({
      model: "gpt-4o", stream: true,
      messages: [{ role: "user", content: prompt }],
    }, { signal: ac.signal });
    let out = ""; let first = Date.now();
    for await (const chunk of stream) {
      if (Date.now() - first > 8000) {
        breaker.recordFailure("STALL"); ac.abort(); break;
      }
      out += chunk.choices[0]?.delta?.content ?? "";
    }
    breaker.recordSuccess(Date.now() - first, 0, out.length / 4);
    return out;
  } catch (e) {
    if (e instanceof OpenAI.APIError && e.status === 429) breaker.recordFailure("429");
    else if (e instanceof OpenAI.APIError && e.status && e.status >= 500) breaker.recordFailure("5xx");
    else if ((e as Error).name === "AbortError") breaker.recordFailure("ABORTED");
    throw e;
  }
}

The 8000ms stall detector is the cheapest signal in the file. It is also the one that catches the failure mode the HTTP-default breaker never sees: a stream that connects, sends the first byte, and then hangs for 60 seconds because the provider’s keep-alive broke. Without the stall detector, the breaker would never trip, the stream would consume a worker for a minute, and the user would stare at a spinner.

The 4 anti-patterns (and the copy-paste fixes)

Every team I have watched wire up an LLM circuit breaker has shipped at least one of the four below. They all work in development. They all fail at 3am.

Anti-pattern 1: fixed 429-only detection

Wrong: counting only HTTP 429s and 5xxes as failures. The breaker never opens on latency, never opens on cost, never opens on stalls. The result: a slow degradation looks like a healthy service until the bill arrives.

// bad: only HTTP-status trip
if (status === 429 || status >= 500) breaker.recordFailure();

Fix: score all six signals per call, and let any one of them trip independently. The reference implementation in section 2 does this — every recordSuccess and recordFailure call evaluates latency p95, cost window, and stall in addition to HTTP status.

Anti-pattern 2: no streaming cancel on open

Wrong: breaker opens on the next call but in-flight streams keep running. You are now paying for 30 seconds of completion that nobody will read. During a real 429 storm this multiplies the cost spike that triggered the breaker in the first place.

// bad: open does not cancel
async precheck() {
  if (this.state === "OPEN") return { ok: false };
  this.inFlight++;
  return { ok: true };
}

Fix: the breaker hands out AbortControllers on every precheck and tracks them in a list. The trip() method calls abortInFlight() the moment the state transitions. The OpenAI client above passes the controller’s signal into the SDK call, so an abort propagates straight to the HTTP socket.

Anti-pattern 3: no cost cap

Wrong: the breaker is a reliability circuit, not a cost circuit. A successful completion that cost $50 because the agent looped 12 times is counted as healthy. The breaker stays CLOSED, the cost window keeps growing, and the on-call engineer finds out the next morning.

// bad: success only checks HTTP
recordSuccess(latencyMs) { this.latencies.push(latencyMs); }

Fix: every recordSuccess also increments the cost window, and precheck() evaluates the window before admitting the next call. The breaker trips on COST_CAP if the per-window USD is over the configured ceiling, and the call that would have pushed it further never goes out.

Anti-pattern 4: swallow-and-retry inside the breaker

Wrong: the breaker catches the call’s exception, retries with exponential backoff, and only reports failure after 5 retries. The breaker becomes a retry wrapper. The state machine never sees the failures; it stays CLOSED; the caller is now waiting 60+ seconds for a response that was never going to succeed.

// bad: retry inside the breaker
async call() {
  for (let i = 0; i < 5; i++) {
    try { return await this.fn(); }
    catch { await sleep(2 ** i * 1000); }
  }
}

Fix: the breaker is a guard, not a wrapper. The caller decides the retry policy. A clean separation looks like: breaker decides if the call goes out; retry library decides if the call goes out again after it failed; caller decides if the call site surfaces a fallback (cached completion, smaller model, queue-and-retry-later). Mixing those concerns inside one object is what produces the swallow-and-retry pattern.

Chaos testing the breaker

A breaker that is not chaos-tested is a breaker that has not been proven to open. The harness below stubs the OpenAI client and verifies three properties: (a) the breaker opens within 3 failures, (b) the breaker cancels in-flight streams on trip, (c) the breaker recovers to CLOSED after a successful half-open probe.

// tests/llm-circuit-breaker.test.ts
import { LlmCircuitBreaker } from "../lib/llm-circuit-breaker.js";
import assert from "node:assert/strict";

async function run() {
  // (a) opens within threshold
  const b1 = new LlmCircuitBreaker({ windowMs: 60000, failureThreshold: 3, costCapUsd: 5,
    p95BaselineMs: 1500, stallMs: 8000, maxConcurrent: 16, openCooldownMs: 30000,
    pricePer1kIn: 0.003, pricePer1kOut: 0.015 });
  for (let i = 0; i < 3; i++) {
    const v = await b1.precheck();
    assert.equal(v.ok, true);
    b1.recordFailure("429");
  }
  const blocked = await b1.precheck();
  assert.equal(blocked.ok, false);
  assert.equal(blocked.reason, "OPEN");
  assert.equal(b1.state, "OPEN");

  // (b) cancels in-flight streams
  const ac = new AbortController();
  b1.aborted.push(ac);
  b1["trip"]("COST_CAP");
  assert.equal(ac.signal.aborted, true);

  // (c) recovers via half-open probe
  const b2 = new LlmCircuitBreaker({ windowMs: 60000, failureThreshold: 3, costCapUsd: 5,
    p95BaselineMs: 1500, stallMs: 8000, maxConcurrent: 16, openCooldownMs: 50,
    pricePer1kIn: 0.003, pricePer1kOut: 0.015 });
  b2.trip("429");
  await new Promise(r => setTimeout(r, 60));
  const probe = await b2.precheck();
  assert.equal(probe.ok, true);
  assert.equal(b2.state, "HALF_OPEN");
  b2.recordSuccess(800, 100, 50);
  assert.equal(b2.state, "CLOSED");

  console.log("OK 3/3 chaos tests passed");
}
run().catch(e => { console.error("FAIL", e); process.exit(1); });

Run it with npx tsx tests/llm-circuit-breaker.test.ts. The 3-of-3 test count is the minimum bar: a breaker that fails any one of these three is unfit for production. In CI, the test runs against the reference implementation in <100ms. In a staging environment, swap the stubbed recordFailure calls for a local mock server that returns real 429/5xx/latency, and the test exercises the same three properties against a live HTTP shape.

Woodpecker CI smoke

Drop the chaos test into your Woodpecker pipeline. The smoke step runs the 3-of-3 assertions on every PR, and a full nightly run exercises the breaker against a real provider sandbox:

# .woodpecker.yml
steps:
  - name: llm-breaker-smoke
    image: node:22
    commands:
      - npm ci
      - npx tsx tests/llm-circuit-breaker.test.ts
    when:
      event: [push, pull_request]
  - name: llm-breaker-nightly
    image: node:22
    secrets: [ openai_sandbox_key ]
    commands:
      - npm ci
      - npx tsx tests/llm-circuit-breaker.live.ts
    when:
      event: [cron]
      cron: "llm-breaker-nightly"

The PR-time smoke is the gate. The nightly run is the long-tail: it runs the breaker against a real provider sandbox with controlled 429 injection and verifies the breaker actually trips in production-shaped latency, not just in the stub. A regression in the breaker that the stub test missed (e.g., a refactor that breaks the AbortController wiring) will be caught within 24 hours. A regression the stub test catches fails the PR before it merges.

Closing thought

An HTTP-default circuit breaker is a useful starting point. An LLM-aware breaker is a different object: it detects six signals instead of one, cancels in-flight streams on trip, and treats cost as a first-class trip condition. The 110-line reference implementation above is the smallest version of that I have shipped across production agents. The four anti-patterns are the four ways teams get it wrong: fixed 429-only detection, no streaming cancel, no cost cap, and swallow-and-retry inside the breaker. The chaos test is the proof that the breaker actually opens, actually cancels, and actually recovers. The CI smoke is what keeps the proof honest.

Ship the breaker. Cancel the streams. Cap the cost. Probe the recovery. Then sleep through the next 429 storm.

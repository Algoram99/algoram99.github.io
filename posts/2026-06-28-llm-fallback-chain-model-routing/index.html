LLM Fallback Chains and Model Routing: 6 Patterns, 5 Anti-Patterns, and a Drop-In Router Runtime

Your agent calls one LLM provider. That provider has a regional outage. Your agent is now dead. No retries will save you because the problem isn't transient load — the provider is down for the next 45 minutes. Here are six model routing patterns that keep your agent alive when the primary model is unreachable, five anti-patterns that make outages worse, and a 140-line router runtime you can drop in today.

TL;DR

  1. Health-check before routing. Don't send traffic to a provider you haven't probed. A lightweight health check (1-token completion) every 30 seconds tells you which providers are alive before you commit real requests.
  2. Cost-aware tiering. Route easy requests (classification, extraction, summarization) to cheap models and hard requests (reasoning, code generation) to expensive ones. A flat "always use GPT-4" strategy costs 10x more than tiered routing.
  3. Probe latency, not just availability. Two providers can both be "up" but one responds in 400ms and the other in 4s. Route to the faster one until the gap closes.
  4. Cache before calling. Before any model call, check a semantic cache. Embedding-based cache hits return identical answers in 2ms with zero API cost. This is the cheapest "fallback" of all — no second model needed.
  5. Match capabilities, not just names. Don't route a vision task to a text-only model just because it's "next in the fallback chain." Route based on what the model can actually do.
  6. Shadow-probe continuously. Send a trickle of real traffic (1%) to backup providers even when the primary is healthy. This detects silent degradation — the provider returns 200 but the quality has dropped.

Why LLM agents need model routing, not just retry

A retry policy (which we covered in our 30th post) handles transient failures: 429s, 503s, timeouts. It retries the same call to the same provider with backoff and jitter. But retry has a blind spot: it cannot save you when the provider is down, not just slow. If OpenAI's API returns 503 for 40 minutes, no amount of backoff fixes that — you need a different provider entirely.

Model routing solves a different problem than retry:

DimensionRetry PolicyModel Router
Failure typeTransient (429, timeout)Sustained (outage, degradation)
ActionRetry same endpointSwitch to different endpoint
Time scaleSeconds (1–30s backoff)Minutes to hours (outage duration)
Cost impactMultiplies cost by retry countCan reduce cost via tiering
Quality impactSame quality (same model)Variable quality (different model)
Composes with circuit breaker?Yes — retry stops when breaker opensYes — router routes around open breaker

The two compose: retry handles transient failures within a single provider; routing switches providers when retry is exhausted. The circuit breaker sits between them — it opens when a provider has failed too many times, and the router routes around the open breaker.

Pattern 1: Health-checked cascade routing

The simplest model router is a cascade: try Provider A first. If A fails, try B. If B fails, try C. The cascade is ordered by preference (cost, quality, latency — whatever you optimize for).

The critical addition is health checking. Before routing to a provider, check whether it's alive. A health check is a 1-token completion request ("ping" → max_tokens: 1) that costs a fraction of a cent and returns in under 500ms from a healthy provider. If the health check fails or times out, the provider is marked unhealthy and skipped entirely.

interface ProviderHealth {
  name: string;
  healthy: boolean;
  lastProbeAt: number;
  lastProbeLatencyMs: number;
  consecutiveFailures: number;
}

class HealthChecker {
  private providers: Map<string, ProviderHealth> = new Map();
  private probeIntervalMs: number;

  constructor(providers: string[], probeIntervalMs = 30_000) {
    this.probeIntervalMs = probeIntervalMs;
    for (const name of providers) {
      this.providers.set(name, {
        name, healthy: true, lastProbeAt: 0,
        lastProbeLatencyMs: 0, consecutiveFailures: 0,
      });
    }
  }

  /** Returns only providers that passed their last health check. */
  getHealthyProviders(): string[] {
    return [...this.providers.values()]
      .filter(p => p.healthy)
      .map(p => p.name);
  }

  /** Probe a single provider. Called on a timer, not per-request. */
  async probe(providerName: string, sendFn: (req: any) => Promise<any>): Promise<void> {
    const provider = this.providers.get(providerName);
    if (!provider) return;

    const start = Date.now();
    try {
      await sendFn({
        model: providerName,
        messages: [{ role: 'user', content: 'ping' }],
        max_tokens: 1,
      });
      const latency = Date.now() - start;
      provider.healthy = true;
      provider.lastProbeAt = Date.now();
      provider.lastProbeLatencyMs = latency;
      provider.consecutiveFailures = 0;
    } catch (err: any) {
      provider.consecutiveFailures++;
      provider.lastProbeAt = Date.now();
      // Mark unhealthy after 2 consecutive failures
      if (provider.consecutiveFailures >= 2) {
        provider.healthy = false;
      }
    }
  }

  /** Mark a provider unhealthy immediately (called on real request failure). */
  markUnhealthy(providerName: string): void {
    const provider = this.providers.get(providerName);
    if (provider) {
      provider.healthy = false;
      provider.consecutiveFailures++;
    }
  }

  /** Restore a provider (after cooldown or manual intervention). */
  markHealthy(providerName: string): void {
    const provider = this.providers.get(providerName);
    if (provider) {
      provider.healthy = true;
      provider.consecutiveFailures = 0;
    }
  }
}

Why 2 consecutive failures, not 1?

A single failed health check can be a transient network blip. If you mark a provider unhealthy on the first failure, you'll oscillate between healthy and unhealthy states every time a packet is dropped. Requiring 2 consecutive failures within the probe window (30s) means the provider must fail twice in a row — a much stronger signal of actual degradation. The trade-off: you lose 30s of detection speed in exchange for stability.

Pattern 2: Cost-aware tiered routing

Not all requests need the same model. A request to classify a support ticket as "refund" or "technical" doesn't need GPT-4-class reasoning. A request to debug a 200-line function does. Tiered routing sends each request to the cheapest model that can handle it.

The key decision is the routing classifier — a cheap, fast function that decides which tier a request belongs to. The classifier itself can be a small model (GPT-3.5, Claude Haiku) or a rule-based heuristic.

type RequestTier = 'simple' | 'standard' | 'complex';

interface TierConfig {
  tier: RequestTier;
  model: string;
  maxTokens: number;
  estimatedCostPerCall: number;
}

const TIERS: TierConfig[] = [
  // Simple: classification, extraction, format conversion
  { tier: 'simple',   model: 'gpt-4o-mini',  maxTokens: 500,  estimatedCostPerCall: 0.0005 },
  // Standard: summarization, rewriting, Q&A on provided context
  { tier: 'standard', model: 'gpt-4o',       maxTokens: 2000, estimatedCostPerCall: 0.005 },
  // Complex: reasoning, code generation, multi-step analysis
  { tier: 'complex',  model: 'o1',           maxTokens: 8000, estimatedCostPerCall: 0.05 },
];

function classifyRequest(messages: Array<{role: string, content: string}>): RequestTier {
  const lastUserMsg = [...messages].reverse().find(m => m.role === 'user');
  if (!lastUserMsg) return 'standard';

  const content = lastUserMsg.content.toLowerCase();
  const tokenEstimate = Math.ceil(content.length / 4);

  // Rule-based heuristic (zero cost, zero latency)
  // Complex signals: code, debugging, multi-step reasoning
  if (content.includes('debug') || content.includes('refactor') ||
      content.includes('implement') || content.includes('architect') ||
      content.includes('analyze') || content.includes('compare') ||
      content.includes('```') || tokenEstimate > 2000) {
    return 'complex';
  }

  // Simple signals: classification, extraction, short Q&A
  if (content.includes('classify') || content.includes('categorize') ||
      content.includes('extract') || content.includes('convert') ||
      content.includes('format') || tokenEstimate < 100) {
    return 'simple';
  }

  return 'standard';
}

function routeToTier(tier: RequestTier, availableModels: string[]): string {
  const config = TIERS.find(t => t.tier === tier)!;
  // If the preferred model is unavailable, fall back to the next tier
  if (availableModels.includes(config.model)) {
    return config.model;
  }
  // Downgrade: try simpler tier first (cheaper)
  const order: RequestTier[] = ['simple', 'standard', 'complex'];
  const currentIdx = order.indexOf(tier);
  for (let i = currentIdx; i < order.length; i++) {
    const fallbackModel = TIERS.find(t => t.tier === order[i])!.model;
    if (availableModels.includes(fallbackModel)) {
      return fallbackModel;
    }
  }
  // Last resort: return whatever is available
  return availableModels[0] ?? TIERS[0].model;
}

Pattern 3: Latency-probing router

Two providers can both be "healthy" but one responds in 400ms and the other in 4 seconds. The latency-probing router tracks rolling P50 latency per provider and routes to the fastest one. This is especially valuable when you have multiple providers serving the same model (e.g., OpenAI direct + Azure OpenAI).

interface LatencyTracker {
  provider: string;
  samples: number[];        // Rolling window of latencies (ms)
  maxSamples: number;       // Keep last N samples (e.g., 20)
}

class LatencyRouter {
  private trackers: Map<string, LatencyTracker> = new Map();

  constructor(providers: string[], maxSamples = 20) {
    for (const name of providers) {
      this.trackers.set(name, { provider: name, samples: [], maxSamples });
    }
  }

  /** Record a latency sample after a request completes. */
  recordLatency(provider: string, latencyMs: number): void {
    const tracker = this.trackers.get(provider);
    if (!tracker) return;
    tracker.samples.push(latencyMs);
    if (tracker.samples.length > tracker.maxSamples) {
      tracker.samples.shift(); // Drop oldest
    }
  }

  /** Get P50 (median) latency for a provider. Lower is better. */
  getP50(provider: string): number {
    const tracker = this.trackers.get(provider);
    if (!tracker || tracker.samples.length === 0) return Infinity;
    const sorted = [...tracker.samples].sort((a, b) => a - b);
    return sorted[Math.floor(sorted.length / 2)];
  }

  /** Route to the provider with the lowest P50 latency. */
  route(healthyProviders: string[]): string {
    if (healthyProviders.length === 0) throw new Error('No healthy providers');
    if (healthyProviders.length === 1) return healthyProviders[0];

    return healthyProviders.reduce((best, current) => {
      return this.getP50(current) < this.getP50(best) ? current : best;
    });
  }
}

Don't use average latency — use P50

Average latency is skewed by outliers. If a provider has 19 fast responses (200ms) and 1 timeout (30,000ms), the average is 1,690ms — making it look slower than a provider that consistently responds in 800ms. P50 (median) ignores the outlier: 200ms, which is the real user experience for 95% of calls. Use P50 for routing decisions, P99 for alerting.

Pattern 4: Semantic cache-first routing

Before calling any model, check whether you've already answered a semantically similar question. A semantic cache uses embeddings to find matches by meaning, not exact text. "How do I handle rate limits in my agent?" and "What's the best way to deal with 429 errors?" are the same question — a semantic cache catches both.

This is the cheapest "fallback" of all: a cache hit costs ~2ms and $0.00. No second model, no failover, no quality degradation. The cache is populated by every successful model call.

import { createHash } from 'crypto';

interface CacheEntry {
  embedding: number[];      // Embedding of the query
  response: string;         // Cached model response
  model: string;            // Which model produced it
  timestamp: number;        // For TTL expiry
  exactHash: string;        // For exact-match fast path
}

class SemanticCache {
  private entries: CacheEntry[] = [];
  private similarityThreshold: number;
  private ttlMs: number;

  constructor(similarityThreshold = 0.92, ttlMs = 3600_000) {
    this.similarityThreshold = similarityThreshold;
    this.ttlMs = ttlMs;
  }

  /** Check exact hash first (free), then semantic similarity (needs embedding). */
  async check(
    query: string,
    embedFn: (text: string) => Promise<number[]>
  ): Promise<CacheEntry | null> {
    const now = Date.now();
    const exactHash = createHash('sha256').update(query).digest('hex');

    // Fast path: exact match (no embedding needed)
    const exact = this.entries.find(
      e => e.exactHash === exactHash && now - e.timestamp < this.ttlMs
    );
    if (exact) return exact;

    // Slow path: semantic match (compute embedding)
    const queryEmbedding = await embedFn(query);
    let bestMatch: CacheEntry | null = null;
    let bestScore = 0;

    for (const entry of this.entries) {
      if (now - entry.timestamp >= this.ttlMs) continue;
      const score = this.cosineSimilarity(queryEmbedding, entry.embedding);
      if (score > bestScore && score >= this.similarityThreshold) {
        bestScore = score;
        bestMatch = entry;
      }
    }

    return bestMatch;
  }

  /** Store a successful response for future cache hits. */
  async store(
    query: string,
    response: string,
    model: string,
    embedFn: (text: string) => Promise<number[]>
  ): Promise<void> {
    const embedding = await embedFn(query);
    const exactHash = createHash('sha256').update(query).digest('hex');
    this.entries.push({
      embedding, response, model,
      timestamp: Date.now(), exactHash,
    });
    // Evict oldest if cache grows beyond 10,000 entries
    if (this.entries.length > 10_000) {
      this.entries.sort((a, b) => b.timestamp - a.timestamp);
      this.entries = this.entries.slice(0, 10_000);
    }
  }

  private cosineSimilarity(a: number[], b: number[]): number {
    let dot = 0, normA = 0, normB = 0;
    for (let i = 0; i < a.length; i++) {
      dot += a[i] * b[i];
      normA += a[i] * a[i];
      normB += b[i] * b[i];
    }
    return dot / (Math.sqrt(normA) * Math.sqrt(normB) || 1);
  }
}

This composes with prompt caching (which caches at the provider level) — semantic caching catches what provider-side caching misses: semantically equivalent but textually different queries.

Pattern 5: Capability-matching router

Not all models can do all things. A fallback chain that blindly cascades from GPT-4 to GPT-3.5 to Claude to Llama will break if the request requires vision and the fallback model is text-only. The capability router matches request requirements to model capabilities before routing.

type ModelCapability = 'text' | 'vision' | 'code' | 'function-calling' | 'json-mode' | 'long-context';

interface ModelProfile {
  name: string;
  capabilities: Set<ModelCapability>;
  maxContextTokens: number;
  costPer1kTokens: number;
}

const MODEL_PROFILES: ModelProfile[] = [
  { name: 'gpt-4o',       capabilities: new Set(['text','vision','code','function-calling','json-mode']), maxContextTokens: 128000, costPer1kTokens: 0.005 },
  { name: 'gpt-4o-mini',  capabilities: new Set(['text','vision','code','function-calling','json-mode']), maxContextTokens: 128000, costPer1kTokens: 0.0005 },
  { name: 'o1',           capabilities: new Set(['text','vision','code']),                                maxContextTokens: 200000, costPer1kTokens: 0.05 },
  { name: 'claude-3.5',   capabilities: new Set(['text','vision','code','function-calling']),             maxContextTokens: 200000, costPer1kTokens: 0.003 },
];

interface RequestRequirements {
  requiredCapabilities: ModelCapability[];
  estimatedInputTokens: number;
}

function routeByCapability(
  requirements: RequestRequirements,
  availableModels: string[]
): string {
  const candidates = MODEL_PROFILES.filter(
    profile => availableModels.includes(profile.name)
  );

  // Filter: must have ALL required capabilities AND fit the context window
  const eligible = candidates.filter(profile => {
    const hasAllCaps = requirements.requiredCapabilities.every(
      cap => profile.capabilities.has(cap)
    );
    const fitsContext = profile.maxContextTokens >= requirements.estimatedInputTokens * 1.2;
    return hasAllCaps && fitsContext;
  });

  if (eligible.length === 0) {
    throw new Error(
      `No model has all required capabilities: ${requirements.requiredCapabilities.join(', ')}`
    );
  }

  // Sort by cost (cheapest first)
  eligible.sort((a, b) => a.costPer1kTokens - b.costPer1kTokens);
  return eligible[0].name;
}

Pattern 6: Shadow traffic health probing

Health checks (Pattern 1) tell you if a provider returns a 200. But a provider can return 200 with degraded quality — truncated responses, slower reasoning, higher hallucination rates. Shadow traffic probing sends 1% of real requests to backup providers and compares the output quality to the primary's. This detects silent degradation before it affects users.

class ShadowProber {
  private shadowRatio: number;       // Fraction of requests to shadow (0.01 = 1%)
  private qualitySamples: Map<string, Array<{
    primaryResponse: string;
    shadowResponse: string;
    timestamp: number;
  }>> = new Map();

  constructor(shadowRatio = 0.01) {
    this.shadowRatio = shadowRatio;
  }

  /** Returns true ~shadowRatio% of the time. */
  shouldShadow(): boolean {
    return Math.random() < this.shadowRatio;
  }

  /** Send the same request to a shadow provider (fire-and-forget). */
  async shadowRequest(
    request: any,
    primaryResponse: string,
    shadowProvider: string,
    sendFn: (provider: string, req: any) => Promise<string>
  ): Promise<void> {
    try {
      const shadowResponse = await sendFn(shadowProvider, request);
      const samples = this.qualitySamples.get(shadowProvider) ?? [];
      samples.push({
        primaryResponse,
        shadowResponse,
        timestamp: Date.now(),
      });
      // Keep last 50 samples
      if (samples.length > 50) samples.shift();
      this.qualitySamples.set(shadowProvider, samples);
    } catch {
      // Shadow failures are expected when the shadow provider is degraded
      // Record the failure but don't crash the primary request
    }
  }

  /** Compare shadow vs primary output quality (call on a schedule). */
  getQualityReport(shadowProvider: string): {
    sampleCount: number;
    avgSimilarity: number;
    lastCheckedAt: number;
  } {
    const samples = this.qualitySamples.get(shadowProvider) ?? [];
    if (samples.length === 0) {
      return { sampleCount: 0, avgSimilarity: 0, lastCheckedAt: 0 };
    }
    // Simple quality proxy: response length ratio
    // (A more sophisticated version would use an LLM-as-judge or BLEU score)
    const ratios = samples.map(s => {
      const len = s.shadowResponse.length / (s.primaryResponse.length || 1);
      return Math.min(len, 2.0); // Cap at 2x
    });
    const avgSimilarity = ratios.reduce((a, b) => a + b, 0) / ratios.length;
    return {
      sampleCount: samples.length,
      avgSimilarity,
      lastCheckedAt: samples[samples.length - 1].timestamp,
    };
  }
}

Anti-pattern 1: Static hardcoded priority

The mistake: Hardcode ['openai', 'anthropic', 'local'] as the fallback order and never change it. When OpenAI is down, every request fails through to Anthropic, doubling Anthropic's load and causing it to rate-limit too.

The fix: Use health-checked routing (Pattern 1). The fallback order is determined at runtime by which providers are actually healthy. When OpenAI is down, the router skips it immediately without wasting a request, and Anthropic doesn't receive the double load because the health check caught the outage before traffic arrived.

Anti-pattern 2: No fallback on 400-class errors

The mistake: Only fall back on 429/500/503. When the primary returns a 400 ("invalid request"), assume the request is genuinely malformed and never try another provider.

The fix: Some 400s are provider-specific, not request-specific. OpenAI rejects certain prompt formats that Anthropic accepts (and vice versa). A 400 from one provider with a message like "content policy violation" might succeed on another provider with a different content filter. Fall back on 400s that have provider-specific error messages ("content_filter", "model_not_found", "context_length_exceeded"). Do NOT fall back on 400s that indicate a genuinely malformed request (empty messages array, missing required fields).

Anti-pattern 3: Hammering the dead provider

The mistake: After a provider goes down, continuously retry the health check every 1 second to detect recovery faster. This generates thousands of failed requests during a 40-minute outage.

The fix: Use exponential backoff on health checks. After the first failure, wait 5s. After the second, wait 10s. After the third, wait 30s. Keep probing every 30s until recovery. This limits health-check traffic to ~80 requests during a 40-minute outage instead of 2,400. The recovery detection latency (30s) is negligible compared to the outage duration.

Anti-pattern 4: Ignoring cost during failover

The mistake: Primary is GPT-4o-mini ($0.0005/call). It goes down. Failover to o1 ($0.05/call). Your daily cost goes from $5 to $500 overnight because every "simple" request now hits the most expensive model.

The fix: Failover must respect tier boundaries (Pattern 2). If the simple-tier model goes down, fail over to the next model in the simple tier, not to the complex tier. If no simple-tier model is available, then upgrade to standard — but alert on it. The alert says: "we're paying 10x normal cost because the cheap provider is down; consider adding a second cheap provider."

Anti-pattern 5: Conflating provider-level and model-level failures

The mistake: Treat "OpenAI is down" the same as "GPT-4o is down." When OpenAI has a partial outage affecting only GPT-4o but not GPT-4o-mini, the router marks the entire OpenAI provider as unhealthy and fails over to Anthropic unnecessarily.

The fix: Track health at the (provider, model) granularity, not just the provider level. A health check probes a specific model on a specific provider. When GPT-4o is down on OpenAI, the router routes to GPT-4o-mini on OpenAI (same provider, different model) before falling over to Anthropic (different provider entirely). This keeps you on the cheaper provider for as long as possible.

Putting it all together: the model router runtime

Here is a complete 140-line TypeScript runtime that combines all six patterns: health checking, cost-tier routing, latency probing, semantic caching, capability matching, and shadow probing — with circuit-breaker integration and cascade failover.

// model-router.ts — drop-in multi-model routing runtime
// Dependencies: none (pure TypeScript, works in Node 18+)

type Capability = 'text' | 'vision' | 'code' | 'function-calling' | 'json-mode';
type Tier = 'simple' | 'standard' | 'complex';

interface RouteResult {
  model: string;
  cached: boolean;
  tier: Tier;
  latencyMs: number;
  providerUsed: string;
}

interface RouteRequest {
  messages: Array<{ role: string; content: string }>;
  requiredCapabilities?: Capability[];
  estimatedInputTokens?: number;
}

class ModelRouter {
  private health: Map<string, { healthy: boolean; failures: number; latencyMs: number; samples: number[] }> = new Map();
  private cache = new Map<string, { response: string; model: string; ts: number }>();
  private circuitBreakers: Map<string, { isOpen: boolean; failures: number; lastFailureAt: number }> = new Map();

  constructor(
    private providers: Array<{ name: string; models: string[]; costPer1k: number; caps: Set<Capability>; ctxTokens: number }>,
    private sendFn: (provider: string, model: string, req: any) => Promise<string>,
    private embedFn?: (text: string) => Promise<number[]>,
  ) {
    for (const p of providers) {
      for (const m of p.models) {
        const key = `${p.name}:${m}`;
        this.health.set(key, { healthy: true, failures: 0, latencyMs: 0, samples: [] });
        this.circuitBreakers.set(key, { isOpen: false, failures: 0, lastFailureAt: 0 });
      }
    }
  }

  /** Main entry point: route a request to the best available model. */
  async route(request: RouteRequest): Promise<RouteResult> {
    const start = Date.now();

    // 1. Check exact cache first
    const cacheKey = JSON.stringify(request.messages);
    const cached = this.cache.get(cacheKey);
    if (cached && Date.now() - cached.ts < 3600_000) {
      return { model: cached.model, cached: true, tier: 'simple' as Tier, latencyMs: Date.now() - start, providerUsed: 'cache' };
    }

    // 2. Classify tier
    const tier = this.classifyTier(request);

    // 3. Build candidate list: healthy + capable + not-circuit-open
    const candidates = this.getCandidates(request, tier);
    if (candidates.length === 0) throw new Error('No eligible models available');

    // 4. Sort by cost (cheapest first), then by latency
    candidates.sort((a, b) => {
      const costDiff = this.getProvider(a)!.costPer1k - this.getProvider(b)!.costPer1k;
      if (Math.abs(costDiff) > 0.001) return costDiff;
      const latA = this.getP50(a);
      const latB = this.getP50(b);
      return latA - latB;
    });

    // 5. Cascade: try each candidate until one succeeds
    let lastError: Error | null = null;
    for (const candidate of candidates) {
      const [provider, model] = candidate.split(':');
      try {
        const response = await this.sendFn(provider, model, request);
        const latency = Date.now() - start;

        // Record success
        this.recordSuccess(candidate, latency);
        this.cache.set(cacheKey, { response, model, ts: Date.now() });

        return { model, cached: false, tier, latencyMs: latency, providerUsed: provider };
      } catch (err: any) {
        lastError = err;
        this.recordFailure(candidate);
        // Continue to next candidate
      }
    }

    throw new Error(`All candidates failed. Last error: ${lastError?.message}`);
  }

  private classifyTier(req: RouteRequest): Tier {
    const tokens = req.estimatedInputTokens ?? 0;
    const lastMsg = req.messages[req.messages.length - 1]?.content.toLowerCase() ?? '';
    if (tokens > 2000 || lastMsg.includes('debug') || lastMsg.includes('implement') ||
        lastMsg.includes('```') || lastMsg.includes('analyze')) return 'complex';
    if (lastMsg.includes('classify') || lastMsg.includes('extract') || tokens < 100) return 'simple';
    return 'standard';
  }

  private getCandidates(req: RouteRequest, tier: Tier): string[] {
    const requiredCaps = req.requiredCapabilities ?? ['text'];
    const inputTokens = req.estimatedInputTokens ?? 0;
    const result: string[] = [];

    for (const p of this.providers) {
      // Check provider has all required capabilities
      if (!requiredCaps.every(c => p.caps.has(c))) continue;
      // Check context window fits
      if (p.ctxTokens < inputTokens * 1.2) continue;

      for (const m of p.models) {
        const key = `${p.name}:${m}`;
        const health = this.health.get(key)!;
        const breaker = this.circuitBreakers.get(key)!;
        // Skip unhealthy models and open circuit breakers
        if (!health.healthy) continue;
        if (breaker.isOpen && Date.now() - breaker.lastFailureAt < 60_000) continue;
        result.push(key);
      }
    }
    return result;
  }

  private recordSuccess(key: string, latencyMs: number): void {
    const h = this.health.get(key)!;
    h.healthy = true;
    h.failures = 0;
    h.samples.push(latencyMs);
    if (h.samples.length > 20) h.samples.shift();
    const b = this.circuitBreakers.get(key)!;
    b.isOpen = false;
    b.failures = 0;
  }

  private recordFailure(key: string): void {
    const h = this.health.get(key)!;
    h.failures++;
    if (h.failures >= 2) h.healthy = false;
    const b = this.circuitBreakers.get(key)!;
    b.failures++;
    b.lastFailureAt = Date.now();
    if (b.failures >= 5) b.isOpen = true;
  }

  private getProvider(key: string) {
    const providerName = key.split(':')[0];
    return this.providers.find(p => p.name === providerName);
  }

  private getP50(key: string): number {
    const h = this.health.get(key);
    if (!h || h.samples.length === 0) return Infinity;
    const sorted = [...h.samples].sort((a, b) => a - b);
    return sorted[Math.floor(sorted.length / 2)];
  }
}

AI Agent Streaming Response Handling: 6 Patterns, 5 Anti-Patterns

Your AI agent calls the LLM API and waits 8 seconds for the full response before showing anything to the user. Users think it's broken. They refresh. They leave. Streaming fixes this — but introduces six new failure modes that nobody warns you about: backpressure, partial JSON, mid-stream errors, cancelled requests, token cost attribution, and connection recovery. Here are six patterns that solve each one, five anti-patterns that silently break production agents, and a 135-line TypeScript runtime you can drop into any agent.

⚡ TL;DR

Streaming LLM responses is not optional in production — it's table stakes. Users expect to see tokens appear in real time. But the moment you switch from await client.complete() to for await (const chunk of stream), you enter a world of partial data, race conditions, and silent failures. This post covers six patterns: (1) Server-Sent Events with backpressure handling so a slow client doesn't OOM your server, (2) Chunked delta accumulation that reconstructs the full response from streaming fragments, (3) Partial JSON streaming parser for when the model streams structured output, (4) Mid-stream error recovery so a connection drop at token 900 of 1000 doesn't throw away everything, (5) Cancellation with partial flush so user "stop" buttons work cleanly, and (6) Per-token cost metering so you can attribute streaming API costs to individual users. Plus five anti-patterns and a complete TypeScript runtime.

The Problem: Streaming Breaks in Six Different Ways

Here's the naive streaming implementation that works in development and fails in production:

// This works locally. It breaks in production.
const stream = await openai.chat.completions.create({
  model: 'gpt-4o',
  messages,
  stream: true,
});

for await (const chunk of stream) {
  const delta = chunk.choices[0]?.delta?.content || '';
  res.write(`data: ${JSON.stringify({ text: delta })}\n\n`);
}
res.write('data: [DONE]\n\n');

Pattern 1: Server-Sent Events with Backpressure

✅ Pattern: Respect the Client's Read Speed

The SSE pattern in the naive example above assumes the client reads as fast as the server writes. In reality, a mobile client on a slow connection may read 10x slower than the LLM streams. Node.js streams use a buffer that grows until memory is exhausted.

The fix: Check res.write()'s return value. If it returns false, the internal buffer is full. Wait for the 'drain' event before sending the next chunk.

// Backpressure-aware SSE stream
async function streamWithBackpressure(
  stream: AsyncIterable<any>,
  res: { write: (data: string) => boolean; writeHead: (code: number, headers: object) => void }
): Promise<void> {
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    'Connection': 'keep-alive',
    'X-Accel-Buffering': 'no', // disable Nginx buffering
  });

  for await (const chunk of stream) {
    const delta = chunk.choices?.[0]?.delta?.content || '';
    const data = `data: ${JSON.stringify({ text: delta, ts: Date.now() })}\n\n`;

    const canContinue = res.write(data);
    if (!canContinue) {
      // Buffer is full. Wait for drain before proceeding.
      await new Promise<void>((resolve) => {
        res.write = ((orig: any) => {
          const patched = (d: string) => orig.call(res, d);
          // Set up one-time drain listener
          const timer = setTimeout(() => resolve(), 30000); // drain timeout
          const onDrain = () => {
            clearTimeout(timer);
            resolve();
          };
          // The response object emits 'drain' when buffer clears
          (res as any).once?.('drain', onDrain);
          return patched;
        })(res.write.bind(res));
      });
    }
  }

  res.write('data: [DONE]\n\n');
}

The key insight: res.write() returns false when the internal buffer exceeds the high-water mark (typically 16KB). Without backpressure handling, a slow client causes the buffer to grow until the process runs out of memory and crashes. This is the #1 production streaming bug.

Pattern 2: Chunked Delta Accumulator

✅ Pattern: Reconstruct the Full Response from Fragments

Streaming responses arrive as deltas — tiny fragments of text. But post-processing (output validation, tool-call parsing, cost attribution, logging) needs the complete response. You need an accumulator that joins fragments in real time without blocking the stream.

The fix: Maintain a growing buffer alongside the stream. Emit each delta to the client immediately, but also accumulate it. When the stream ends, you have the full text.

// Delta accumulator that reconstructs full text
class DeltaAccumulator {
  private fragments: string[] = [];
  private toolCallFragments: Map<number, any> = new Map();
  private finishReason: string | null = null;
  private model: string | null = null;

  ingest(chunk: any): { delta: string; isComplete: boolean } {
    const choice = chunk.choices?.[0];
    if (!choice) return { delta: '', isComplete: false };

    const delta = choice.delta?.content || '';

    // Accumulate text
    if (delta) {
      this.fragments.push(delta);
    }

    // Accumulate tool calls (they arrive in fragments too)
    if (choice.delta?.tool_calls) {
      for (const tc of choice.delta.tool_calls) {
        const idx = tc.index ?? 0;
        const existing = this.toolCallFragments.get(idx) || { id: '', name: '', args: '' };
        if (tc.id) existing.id = tc.id;
        if (tc.function?.name) existing.name += tc.function.name;
        if (tc.function?.arguments) existing.args += tc.function.arguments;
        this.toolCallFragments.set(idx, existing);
      }
    }

    if (choice.finish_reason) {
      this.finishReason = choice.finish_reason;
      this.model = chunk.model || null;
    }

    return { delta, isComplete: choice.finish_reason !== null };
  }

  getFullText(): string {
    return this.fragments.join('');
  }

  getToolCalls(): Array<{ id: string; name: string; args: string }> {
    return Array.from(this.toolCallFragments.values());
  }

  getSummary(): { textLength: number; toolCallCount: number; finishReason: string; model: string } {
    return {
      textLength: this.getFullText().length,
      toolCallCount: this.toolCallFragments.size,
      finishReason: this.finishReason || 'incomplete',
      model: this.model || 'unknown',
    };
  }
}

Why an array instead of string concatenation? Because strings.push(delta) and strings.join('') at the end is O(n) in total, whereas repeated fullText += delta is O(n²) when the engine can't optimize. For 1,000 fragments averaging 5 characters, the difference is negligible. For 10,000 fragments, it's measurable.

Pattern 3: Partial JSON Streaming Parser

✅ Pattern: Parse Incomplete JSON Without Crashing

When your agent requests structured output (e.g., response_format: { type: "json_object" }), the model streams partial JSON token by token. After 50 tokens you might have {"action": "search", "query": "best pract. A standard JSON.parse() throws. Your agent crashes mid-stream.

The fix: A fault-tolerant JSON parser that returns a "best effort" partial parse. It closes open strings, adds missing closing braces, and returns whatever it can reconstruct.

// Partial JSON parser for streaming structured output
function parsePartialJson(input: string): { parsed: any | null; isComplete: boolean } {
  // Strategy: try to close incomplete JSON by adding missing brackets/quotes

  // Attempt direct parse first
  try {
    const result = JSON.parse(input);
    return { parsed: result, isComplete: true };
  } catch {
    // Not complete yet — try to repair
  }

  // Count unmatched brackets
  let repaired = input.trim();
  if (!repaired.startsWith('{') && !repaired.startsWith('[')) {
    return { parsed: null, isComplete: false };
  }

  // Check if we're mid-string (odd number of unescaped quotes)
  let inString = false;
  let escaped = false;
  let braceDepth = 0;
  let bracketDepth = 0;
  let lastKeyEnd = -1;

  for (let i = 0; i < repaired.length; i++) {
    const ch = repaired[i];
    if (escaped) { escaped = false; continue; }
    if (ch === '\\') { escaped = true; continue; }
    if (ch === '"') {
      inString = !inString;
      if (!inString) lastKeyEnd = i;
      continue;
    }
    if (inString) continue;
    if (ch === '{') braceDepth++;
    if (ch === '}') braceDepth--;
    if (ch === '[') bracketDepth++;
    if (ch === ']') bracketDepth--;
  }

  // Close open string
  if (inString) {
    repaired += '"';
  }

  // Remove trailing comma if present
  repaired = repaired.replace(/,\s*$/, '');

  // If we're mid-value (after a colon, incomplete), try removing the last key-value
  // and closing what we have
  const colonIndex = repaired.lastIndexOf(':');
  if (colonIndex > lastKeyEnd) {
    // We have "key": <incomplete value> — truncate to just before the key
    const lastComma = repaired.lastIndexOf(',', colonIndex);
    if (lastComma > 0) {
      repaired = repaired.substring(0, lastComma);
    } else {
      // Only one key, nothing to return
      return { parsed: null, isComplete: false };
    }
  }

  // Close open brackets
  for (let i = 0; i < bracketDepth; i++) repaired += ']';
  for (let i = 0; i < braceDepth; i++) repaired += '}';

  try {
    return { parsed: JSON.parse(repaired), isComplete: false };
  } catch {
    return { parsed: null, isComplete: false };
  }
}

This parser is intentionally conservative. It would rather return null than return wrong data. When it does return a partial parse, the isComplete: false flag tells your agent "this is a preview, don't act on it yet." This lets you show users a real-time preview of structured tool calls as they stream, without crashing when the JSON is half-finished.

Pattern 4: Mid-Stream Error Recovery

✅ Pattern: Don't Throw Away 90% of a Good Response

A network blip at token 900 of a 1,000-token response throws an AbortError or SOCKET_HANG_UP. The naive implementation catches it, returns nothing, and retries the entire request. The user waits another 8 seconds. The API bill doubles.

The fix: Catch stream errors, check if you have enough partial content to return, and flush what you have with a truncated: true flag.

// Mid-stream error recovery wrapper
async function streamWithRecovery(
  createStream: () => Promise<AsyncIterable<any>>,
  options: {
    minAcceptableTokens?: number; // flush if we got at least this many
    maxRetries?: number;
    flushOnError?: (partial: string, error: Error) => void;
  } = {}
): Promise<{ text: string; recovered: boolean; error: Error | null }> {
  const { minAcceptableTokens = 50, maxRetries = 1, flushOnError } = options;
  const accumulator = new DeltaAccumulator();

  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      const stream = await createStream();
      for await (const chunk of stream) {
        const { delta } = accumulator.ingest(chunk);
        // Forward delta to consumer here...
      }

      // Stream completed normally
      return { text: accumulator.getFullText(), recovered: false, error: null };

    } catch (err) {
      const partialText = accumulator.getFullText();
      const partialTokens = Math.ceil(partialText.length / 4); // rough estimate

      if (partialTokens >= minAcceptableTokens) {
        // We have enough content to return
        flushOnError?.(partialText, err as Error);
        return {
          text: partialText,
          recovered: true,
          error: err as Error,
        };
      }

      if (attempt < maxRetries) {
        // Not enough content. Retry from scratch.
        continue;
      }

      // Exhausted retries, not enough content
      throw err;
    }
  }

  // Should not reach here
  throw new Error('Stream recovery exhausted');
}

The minAcceptableTokens threshold is a judgment call. For a chat agent, 50 tokens (about 37 words) is often enough to be useful — the user sees a partial answer instead of nothing. For a code-generation agent, you might set it to 0 (no partial code) because half a function is worse than no function. The key is making the decision explicit instead of letting the default "throw and retry everything" behavior waste API calls.

Pattern 5: Cancellation with Partial Flush

✅ Pattern: Let Users Stop Without Leaking Tokens

When a user clicks "Stop generating," the stream must be cancelled immediately. But three things go wrong: (1) the API keeps charging you for the full response because the connection isn't closed server-side, (2) the partial response is thrown away, and (3) the AbortController fires an error that your error handler treats as a real failure.

The fix: Use an AbortController, distinguish cancellation from error, and flush partial content as a "user-cancelled" result.

// Cancellation-aware streaming
class StreamController {
  private abortController = new AbortController();
  private accumulator = new DeltaAccumulator();
  private isCancelled = false;

  async stream(
    createStream: (signal: AbortSignal) => Promise<AsyncIterable<any>>,
    onDelta: (text: string) => void
  ): Promise<{
    text: string;
    status: 'complete' | 'cancelled' | 'error';
    tokensConsumed: number;
  }> {
    try {
      const stream = await createStream(this.abortController.signal);

      for await (const chunk of stream) {
        if (this.isCancelled) break;
        const { delta } = this.accumulator.ingest(chunk);
        if (delta) onDelta(delta);
      }

      return {
        text: this.accumulator.getFullText(),
        status: this.isCancelled ? 'cancelled' : 'complete',
        tokensConsumed: Math.ceil(this.accumulator.getFullText().length / 4),
      };

    } catch (err: any) {
      // Distinguish cancellation from real errors
      if (err.name === 'AbortError' || this.isCancelled) {
        return {
          text: this.accumulator.getFullText(),
          status: 'cancelled',
          tokensConsumed: Math.ceil(this.accumulator.getFullText().length / 4),
        };
      }

      return {
        text: this.accumulator.getFullText(),
        status: 'error',
        tokensConsumed: Math.ceil(this.accumulator.getFullText().length / 4),
      };
    }
  }

  cancel(): void {
    this.isCancelled = true;
    this.abortController.abort();
  }
}

// const controller = new StreamController();

//   (delta) => appendToUI(delta)
// );
// // User clicks "Stop":

The critical detail is the this.isCancelled flag checked at the top of the for await loop. The AbortController.abort() signal tells the API to stop generating, but there may be buffered chunks still in flight. The flag ensures we stop processing them immediately, and the catch block converts AbortError into a clean "cancelled" status rather than treating it as a server failure.

Pattern 6: Per-Token Cost Metering

✅ Pattern: Attribute Streaming Costs in Real Time

Streaming responses don't include a usage field until the very last chunk (and some providers omit it entirely from streaming). Without per-request cost data, you can't meter costs per user, set spending limits, or alert on cost anomalies. You're flying blind.

The fix: Count tokens as they stream (using a character-to-token heuristic or a tokenizer), multiply by your provider's per-token price, and emit cost events.

// Per-token cost meter for streaming responses
class StreamCostMeter {
  private inputTokens = 0;
  private outputTokens = 0;
  private pricing: Record<string, { input: number; output: number }>;

  constructor() {
    // Pricing per 1K tokens (update from your provider's current pricing)
    this.pricing = {
      'gpt-4o':       { input: 0.0025, output: 0.01 },
      'gpt-4o-mini':  { input: 0.00015, output: 0.0006 },
      'claude-3-5-sonnet': { input: 0.003, output: 0.015 },
      'claude-3-haiku': { input: 0.00025, output: 0.00125 },
    };
  }

  setInputTokens(promptTokens: number): void {
    this.inputTokens = promptTokens;
  }

  countOutputToken(delta: string): void {
    // Heuristic: ~4 characters per token for English text
    this.outputTokens += Math.ceil(delta.length / 4);
  }

  // If the final chunk has actual usage, use that instead of the heuristic
  reconcileWithUsage(actualOutputTokens: number): void {
    this.outputTokens = actualOutputTokens;
  }

  getCost(model: string): { input: number; output: number; total: number; outputTokens: number } {
    const price = this.pricing[model] || { input: 0.003, output: 0.015 };
    const inputCost = (this.inputTokens / 1000) * price.input;
    const outputCost = (this.outputTokens / 1000) * price.output;
    return {
      input: inputCost,
      output: outputCost,
      total: inputCost + outputCost,
      outputTokens: this.outputTokens,
    };
  }
}

The reconcileWithUsage method is important: the character heuristic overestimates by 10-20% for code-heavy responses (code uses more characters per token due to symbols) and underestimates for JSON-heavy responses. When the final chunk provides the actual token count, use it. Between requests, the heuristic gives you a "good enough" running estimate for real-time dashboards.

Five Anti-Patterns That Break Streaming in Production

❌ Anti-Pattern 1: Buffer the Entire Response Before Returning

The mistake: Consuming the entire stream into a string, then returning it to the client all at once. This defeats the entire purpose of streaming — the user waits just as long as a non-streaming request, but you've added complexity for no benefit.

The fix: Always forward deltas to the client as they arrive. Use the DeltaAccumulator (Pattern 2) alongside the live stream, not instead of it. The accumulator is for post-processing; the live delta is for the user experience.

❌ Anti-Pattern 2: Ignore Backpressure Until OOM

The mistake: Calling res.write(delta) in a tight loop without checking the return value. Under load (100+ concurrent slow clients), the write buffer grows unboundedly. The Node.js process hits its memory limit and restarts, dropping all active streams.

The fix: Use Pattern 1. Check res.write() return value. If false, await 'drain'. Set a drain timeout (30s) to avoid hanging on a dead connection.

❌ Anti-Pattern 3: Swallow Stream Errors Silently

The mistake: Wrapping the entire for await loop in a try/catch that logs the error but continues as if the stream completed. The user sees a truncated response. The agent treats it as successful. Downstream code processes incomplete data.

The fix: Use Pattern 4. Distinguish between errors that occur before any content arrives (retry from scratch), errors that occur after meaningful content (flush partial with truncated: true), and errors that the client should see (propagate to UI). Never silently continue after a stream error.

❌ Anti-Pattern 4: No Cancellation Token

The mistake: Starting a stream with no way to cancel it. The user clicks "Stop" but the frontend has no reference to the AbortController. The stream continues consuming tokens for 5-10 more seconds. You pay for a full response that nobody reads.

The fix: Use Pattern 5. Create an AbortController before starting the stream. Pass its signal to the API call. Expose controller.cancel() to the UI layer. When cancelled, close the connection immediately and flush partial content.

❌ Anti-Pattern 5: Stream Raw Tokens to the User Without Sanitizing

The mistake: Forwarding LLM deltas directly to the user's DOM via innerHTML or similar. The model outputs <script>alert('xss')</script> inside a code block. Your "real-time" rendering executes it.

The fix: Always render streamed content as text nodes (textContent) or through a sanitizing markdown renderer. Never use innerHTML for live-streamed LLM output. Sanitize after the full response is assembled, not during streaming — partial markdown can produce invalid HTML that renders differently on each token.

The Drop-In Stream Handler Runtime

Here's a complete, zero-dependency TypeScript runtime that combines all six patterns. It wraps any streaming LLM API (OpenAI, Anthropic, custom) and handles backpressure, delta accumulation, partial JSON, error recovery, cancellation, and cost metering.

/**
 * stream-handler.ts
 * Zero-dependency streaming response handler for LLM agents.
 *
 * Usage:
 *   const handler = new StreamHandler<any>();
 *   const result = await handler.run(
 *     (signal) => openai.chat.completions.create({ ...options, stream: true }, { signal }),
 *     { model: 'gpt-4o', inputTokens: 500, onDelta: (text) => ui.append(text) }
 *   );
 *   // result.text, result.toolCalls, result.cost, result.status
 */

type StreamResult = {
  text: string;
  toolCalls: Array<{ id: string; name: string; args: string }>;
  status: 'complete' | 'cancelled' | 'recovered' | 'error';
  error: Error | null;
  cost: { input: number; output: number; total: number; outputTokens: number };
  durationMs: number;
};

interface StreamOptions {
  model: string;
  inputTokens?: number;
  onDelta?: (text: string) => void;
  minAcceptableTokens?: number;
  pricing?: Record<string, { input: number; output: number }>;
}

class StreamHandler<Chunk> {
  private abortController = new AbortController();
  private fragments: string[] = [];
  private toolCallFrags: Map<number, { id: string; name: string; args: string }> = new Map();
  private finishReason: string | null = null;
  private isCancelled = false;

  get signal(): AbortSignal { return this.abortController.signal; }

  cancel(): void {
    this.isCancelled = true;
    this.abortController.abort();
  }

  ingest(chunk: Chunk): string {
    const c = chunk as any;
    const delta = c.choices?.[0]?.delta?.content || '';

    if (delta) {
      this.fragments.push(delta);
    }

    if (c.choices?.[0]?.delta?.tool_calls) {
      for (const tc of c.choices[0].delta.tool_calls) {
        const idx = tc.index ?? 0;
        const ex = this.toolCallFrags.get(idx) || { id: '', name: '', args: '' };
        if (tc.id) ex.id = tc.id;
        if (tc.function?.name) ex.name += tc.function.name;
        if (tc.function?.arguments) ex.args += tc.function.arguments;
        this.toolCallFrags.set(idx, ex);
      }
    }

    if (c.choices?.[0]?.finish_reason) {
      this.finishReason = c.choices[0].finish_reason;
    }

    return delta;
  }

  getText(): string { return this.fragments.join(''); }

  getToolCalls() { return Array.from(this.toolCallFrags.values()); }

  async run(
    createStream: (signal: AbortSignal) => Promise<AsyncIterable<Chunk>>,
    options: StreamOptions
  ): Promise<StreamResult> {
    const startTime = Date.now();
    const { model, inputTokens = 0, onDelta, minAcceptableTokens = 50 } = options;
    const pricing = options.pricing || {
      'gpt-4o': { input: 0.0025, output: 0.01 },
      'claude-3-5-sonnet': { input: 0.003, output: 0.015 },
    };
    const price = pricing[model] || { input: 0.003, output: 0.015 };

    try {
      const stream = await createStream(this.signal);

      for await (const chunk of stream) {
        if (this.isCancelled) break;
        const delta = this.ingest(chunk);
        if (delta && onDelta) onDelta(delta);
      }

      const outputTokens = Math.ceil(this.getText().length / 4);
      return {
        text: this.getText(),
        toolCalls: this.getToolCalls(),
        status: this.isCancelled ? 'cancelled' : 'complete',
        error: null,
        cost: {
          input: (inputTokens / 1000) * price.input,
          output: (outputTokens / 1000) * price.output,
          total: (inputTokens / 1000) * price.input + (outputTokens / 1000) * price.output,
          outputTokens,
        },
        durationMs: Date.now() - startTime,
      };

    } catch (err: any) {
      const partialText = this.getText();
      const partialTokens = Math.ceil(partialText.length / 4);

      if (err.name === 'AbortError' || this.isCancelled) {
        return {
          text: partialText,
          toolCalls: this.getToolCalls(),
          status: 'cancelled',
          error: err,
          cost: {
            input: (inputTokens / 1000) * price.input,
            output: (partialTokens / 1000) * price.output,
            total: (inputTokens / 1000) * price.input + (partialTokens / 1000) * price.output,
            outputTokens: partialTokens,
          },
          durationMs: Date.now() - startTime,
        };
      }

      // Mid-stream error with enough content to flush
      if (partialTokens >= minAcceptableTokens) {
        return {
          text: partialText,
          toolCalls: this.getToolCalls(),
          status: 'recovered',
          error: err,
          cost: {
            input: (inputTokens / 1000) * price.input,
            output: (partialTokens / 1000) * price.output,
            total: (inputTokens / 1000) * price.input + (partialTokens / 1000) * price.output,
            outputTokens: partialTokens,
          },
          durationMs: Date.now() - startTime,
        };
      }

      return {
        text: partialText,
        toolCalls: this.getToolCalls(),
        status: 'error',
        error: err,
        cost: {
          input: (inputTokens / 1000) * price.input,
          output: (partialTokens / 1000) * price.output,
          total: (inputTokens / 1000) * price.input + (partialTokens / 1000) * price.output,
          outputTokens: partialTokens,
        },
        durationMs: Date.now() - startTime,
      };
    }
  }
}

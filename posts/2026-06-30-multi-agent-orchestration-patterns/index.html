Multi-Agent Orchestration Patterns: 6 Proven Architectures for Coordinating AI Agents

June 30, 2026 · 12 min read

⚡ TL;DR

When a single LLM agent cannot handle a complex task alone, you need multiple agents working together — but coordinating them is where most multi-agent systems fail. This guide walks through 6 production-tested orchestration patterns: sequential pipeline, parallel fan-out/fan-in, hierarchical supervisor, peer-to-peer handoff, auction-based task allocation, and event-driven choreography. Each pattern includes TypeScript code, tradeoffs, and when to use it. The most common starting point is the sequential pipeline (one agent's output feeds the next); the most robust for complex workflows is the hierarchical supervisor (a coordinator agent routes sub-tasks to specialist agents). The critical anti-pattern to avoid at all costs: uncontrolled peer-to-peer delegation, where agents recursively spawn sub-agents without depth limits or budget caps.

🚨 Why This Matters

Multi-agent systems fail in production for predictable reasons: infinite delegation loops where Agent A calls Agent B which calls Agent A; token budget explosions where N agents each consume full context windows; cascade failures where one agent's bad output poisons downstream agents; and observability black holes where no one can reconstruct which agent made which decision. The orchestration pattern you choose is the single biggest determinant of whether your multi-agent system is debuggable, cost-controlled, and reliable.

Pattern 1: Sequential Pipeline (Chain of Agents)

The simplest multi-agent pattern: each agent in a fixed sequence receives the previous agent's output as input, transforms it, and passes it forward. This is the multi-agent equivalent of a Unix pipe — agent1 | agent2 | agent3. Each agent has a single responsibility and a well-defined input/output contract.

When to Use

  • The task decomposes into a fixed, linear sequence of steps
  • Each step requires a different system prompt, model, or toolset
  • Latency is acceptable (total = sum of all agent latencies)
  • You want simplicity and debuggability above all

Implementation

/**
 * Sequential Pipeline Pattern
 * Each agent receives the previous agent's output.
 * Failures propagate immediately (fail-fast).
 */

interface AgentResult {
  agentId: string;
  output: string;
  tokensUsed: number;
  durationMs: number;
  status: 'success' | 'error';
}

interface PipelineAgent {
  id: string;
  systemPrompt: string;
  model: string;
  execute: (input: string) => Promise<string>;
}

class SequentialPipeline {
  private agents: PipelineAgent[];
  private maxTotalTokens: number;
  private totalTokensUsed: number = 0;

  constructor(agents: PipelineAgent[], maxTotalTokens: number = 50_000) {
    this.agents = agents;
    this.maxTotalTokens = maxTotalTokens;
  }

  async run(initialInput: string): Promise<AgentResult[]> {
    const results: AgentResult[] = [];
    let currentInput = initialInput;

    for (const agent of this.agents) {
      // Budget guard: stop before token explosion
      if (this.totalTokensUsed >= this.maxTotalTokens) {
        throw new Error(
          `Token budget exhausted: ${this.totalTokensUsed} / ${this.maxTotalTokens}. ` +
          `Agent ${agent.id} was not executed.`
        );
      }

      const startTime = Date.now();
      try {
        const output = await agent.execute(currentInput);
        const durationMs = Date.now() - startTime;

        // Estimate tokens (rough: 1 token ~ 4 chars)
        const tokensUsed = Math.ceil((currentInput.length + output.length) / 4);
        this.totalTokensUsed += tokensUsed;

        const result: AgentResult = {
          agentId: agent.id,
          output,
          tokensUsed,
          durationMs,
          status: 'success',
        };
        results.push(result);

        // Pass output to next agent
        currentInput = output;
      } catch (err) {
        const result: AgentResult = {
          agentId: agent.id,
          output: '',
          tokensUsed: 0,
          durationMs: Date.now() - startTime,
          status: 'error',
        };
        results.push(result);

        // Fail-fast: propagate error
        throw new Error(
          `Agent ${agent.id} failed: ${(err as Error).message}. ` +
          `Pipeline aborted after ${results.length} of ${this.agents.length} agents.`
        );
      }
    }

    return results;
  }

  getTotalTokensUsed(): number {
    return this.totalTokensUsed;
  }
}

// Usage: Research -> Draft -> Review -> Polish
const pipeline = new SequentialPipeline([
  {
    id: 'researcher',
    systemPrompt: 'You are a research agent. Find 3 key facts about the topic.',
    model: 'gpt-4o',
    execute: async (input) => { /* call LLM with input */ return 'FACTS: ...'; },
  },
  {
    id: 'drafter',
    systemPrompt: 'You are a writer. Write a blog post from the research.',
    model: 'gpt-4o',
    execute: async (input) => { /* call LLM with research */ return 'DRAFT: ...'; },
  },
  {
    id: 'reviewer',
    systemPrompt: 'You are an editor. Review and suggest improvements.',
    model: 'gpt-4o-mini',
    execute: async (input) => { /* call LLM with draft */ return 'REVIEWED: ...'; },
  },
]);

const results = await pipeline.run('The impact of vector databases on RAG performance');
console.log(`Pipeline used ${pipeline.getTotalTokensUsed()} tokens across ${results.length} agents`);

Complexity: Low   Debuggability: High   Token Efficiency: High

Tradeoff: Latency is additive. If each agent takes 3 seconds, a 5-agent pipeline takes 15 seconds. There is no parallelism — each agent waits for the previous one to finish.

Pattern 2: Parallel Fan-Out / Fan-In

When a task can be decomposed into independent sub-tasks, run them in parallel. A splitter agent breaks the task into N parts, each part is processed by a worker agent simultaneously, and a merger agent combines the results. This is the multi-agent equivalent of Promise.all().

When to Use

  • Sub-tasks are independent (no dependency between them)
  • Latency matters more than token cost (parallel is faster but uses more total tokens)
  • The merger can meaningfully combine disparate outputs
  • You need to process multiple data sources simultaneously

Implementation

/**
 * Parallel Fan-Out / Fan-In Pattern
 * Splitter decomposes -> workers process in parallel -> merger combines.
 * Includes max concurrency limit and per-worker timeout.
 */

interface SubTask {
  id: string;
  description: string;
  input: string;
}

interface WorkerResult {
  subTaskId: string;
  output: string;
  status: 'success' | 'error' | 'timeout';
  tokensUsed: number;
}

class FanOutFanIn {
  private maxConcurrency: number;
  private workerTimeoutMs: number;
  private maxWorkers: number;

  constructor(options: {
    maxConcurrency?: number;
    workerTimeoutMs?: number;
    maxWorkers?: number;
  } = {}) {
    this.maxConcurrency = options.maxConcurrency ?? 5;
    this.workerTimeoutMs = options.workerTimeoutMs ?? 30_000;
    this.maxWorkers = options.maxWorkers ?? 10;
  }

  async run<T>(
    input: string,
    splitter: (input: string) => Promise<SubTask[]>,
    worker: (subTask: SubTask) => Promise<string>,
    merger: (results: WorkerResult[]) => Promise<T>
  ): Promise<T> {
    // Phase 1: Fan-out (split)
    const subTasks = await splitter(input);

    if (subTasks.length > this.maxWorkers) {
      console.warn(
        `Splitter produced ${subTasks.length} sub-tasks; ` +
        `capping at ${this.maxWorkers}. Excess tasks dropped.`
      );
    }
    const capped = subTasks.slice(0, this.maxWorkers);

    // Phase 2: Parallel execution with concurrency limit
    const results: WorkerResult[] = [];
    const executing: Promise<void>[] = [];

    for (const subTask of capped) {
      // If at concurrency limit, wait for one to finish
      if (executing.length >= this.maxConcurrency) {
        await Promise.race(executing);
      }

      const promise = this.executeWorker(worker, subTask)
        .then((result) => { results.push(result); })
        .catch((err) => {
          results.push({
            subTaskId: subTask.id,
            output: '',
            status: 'error',
            tokensUsed: 0,
          });
        })
        .finally(() => {
          const idx = executing.indexOf(promise);
          if (idx >= 0) executing.splice(idx, 1);
        });

      executing.push(promise);
    }

    await Promise.all(executing);

    // Phase 3: Fan-in (merge)
    return merger(results);
  }

  private async executeWorker(
    worker: (subTask: SubTask) => Promise<string>,
    subTask: SubTask
  ): Promise<WorkerResult> {
    try {
      // Race worker against timeout
      const output = await Promise.race([
        worker(subTask),
        new Promise<never>((_, reject) =>
          setTimeout(() => reject(new Error('timeout')), this.workerTimeoutMs)
        ),
      ]);

      const tokensUsed = Math.ceil(output.length / 4);
      return { subTaskId: subTask.id, output, status: 'success', tokensUsed };
    } catch (err) {
      const isTimeout = (err as Error).message === 'timeout';
      return {
        subTaskId: subTask.id,
        output: '',
        status: isTimeout ? 'timeout' : 'error',
        tokensUsed: 0,
      };
    }
  }
}

// Usage: Analyze 3 repos in parallel, merge findings
const fanOutFanIn = new FanOutFanIn({
  maxConcurrency: 3,
  workerTimeoutMs: 20_000,
  maxWorkers: 5,
});

const report = await fanOutFanIn.run(
  'Analyze security posture of langchain, llama-index, and autogen repos',
  // Splitter
  async (input) => [
    { id: 'r1', description: 'Analyze langchain', input: 'langchain' },
    { id: 'r2', description: 'Analyze llama-index', input: 'llama-index' },
    { id: 'r3', description: 'Analyze autogen', input: 'autogen' },
  ],
  // Worker (runs in parallel)
  async (subTask) => {
    // Call LLM to analyze the repo
    return `Security analysis of ${subTask.input}: ...`;
  },
  // Merger
  async (results) => {
    const successful = results.filter(r => r.status === 'success');
    const failed = results.filter(r => r.status !== 'success');
    return {
      summary: `${successful.length}/${results.length} repos analyzed successfully`,
      failed: failed.map(f => f.subTaskId),
      details: successful.map(s => s.output),
    };
  }
);

Complexity: Medium   Latency: Low (parallel)   Token Cost: Medium (N agents each consume full context)

Tradeoff: Total token cost scales linearly with the number of workers. If each worker uses 5K tokens and you fan out to 10 workers, you spend 50K tokens on the fan-out phase alone. The splitter and merger add overhead on top.

Pattern 3: Hierarchical Supervisor

A supervisor agent acts as the coordinator. It receives the user's request, decides which specialist agents to invoke, routes the task, collects results, and decides whether the task is complete or needs another round. The supervisor holds the conversation state and makes routing decisions — the specialist agents are stateless workers.

This is the pattern used by LangGraph's StateGraph with a supervisor node, OpenAI's Swarm framework, and most production multi-agent systems.

When to Use

  • The task requires dynamic routing (you don't know upfront which agents to call)
  • Tasks may require multiple rounds (supervisor iterates until done)
  • You need a single entry point for observability and cost control
  • Different sub-tests require fundamentally different tools or models

Implementation

/**
 * Hierarchical Supervisor Pattern
 * Supervisor decides routing, specialists execute, loop until done.
 * Includes max iterations, token budget, and depth tracking.
 */

type AgentName = 'researcher' | 'coder' | 'reviewer' | 'writer' | 'supervisor';

interface SupervisorDecision {
  nextAgent: AgentName | 'DONE';
  taskForAgent: string;
  reason: string;
}

interface SpecialistAgent {
  name: AgentName;
  description: string;
  execute: (task: string, context: string) => Promise<string>;
}

interface ConversationTurn {
  agent: AgentName;
  input: string;
  output: string;
  timestamp: number;
}

class HierarchicalSupervisor {
  private specialists: Map<AgentName, SpecialistAgent>;
  private maxIterations: number;
  private maxTokens: number;
  private totalTokens: number = 0;
  private conversationLog: ConversationTurn[] = [];

  constructor(options: {
    specialists: SpecialistAgent[];
    maxIterations?: number;
    maxTokens?: number;
  }) {
    this.specialists = new Map(options.specialists.map(s => [s.name, s]));
    this.maxIterations = options.maxIterations ?? 10;
    this.maxTokens = options.maxTokens ?? 100_000;
  }

  async run(userRequest: string): Promise<{ result: string; turns: ConversationTurn[]; tokensUsed: number }> {
    let context = userRequest;
    let iteration = 0;

    while (iteration < this.maxIterations) {
      // Budget guard
      if (this.totalTokens >= this.maxTokens) {
        return {
          result: `Supervisor hit token budget (${this.maxTokens}) after ${iteration} iterations.`,
          turns: this.conversationLog,
          tokensUsed: this.totalTokens,
        };
      }

      // Supervisor decides next step
      const decision = await this.supervisorDecide(context, iteration);

      if (decision.nextAgent === 'DONE') {
        return {
          result: decision.taskForAgent, // final answer
          turns: this.conversationLog,
          tokensUsed: this.totalTokens,
        };
      }

      // Route to specialist
      const specialist = this.specialists.get(decision.nextAgent);
      if (!specialist) {
        throw new Error(`Supervisor routed to unknown agent: ${decision.nextAgent}`);
      }

      const startTime = Date.now();
      const output = await specialist.execute(decision.taskForAgent, context);
      const tokensUsed = Math.ceil((decision.taskForAgent.length + output.length) / 4);
      this.totalTokens += tokensUsed;

      // Log the turn
      this.conversationLog.push({
        agent: decision.nextAgent,
        input: decision.taskForAgent,
        output,
        timestamp: startTime,
      });

      // Feed output back into context for next supervisor decision
      context += `\n\n[${decision.nextAgent}]: ${output}`;
      iteration++;
    }

    return {
      result: `Supervisor hit max iterations (${this.maxIterations}) without completing.`,
      turns: this.conversationLog,
      tokensUsed: this.totalTokens,
    };
  }

  private async supervisorDecide(context: string, iteration: number): Promise<SupervisorDecision> {
    const availableAgents = Array.from(this.specialists.values())
      .map(s => `- ${s.name}: ${s.description}`)
      .join('\n');

    const prompt = `You are a supervisor agent coordinating a team of specialists.

Available agents:
${availableAgents}

Conversation so far:
${context.slice(-4000)}

Iteration: ${iteration + 1} / ${this.maxIterations}

Decide the next step. Respond in JSON:
{"nextAgent": "<agent_name or DONE>", "taskForAgent": "<specific instruction>", "reason": "<why>"}`;

    // In production, call your LLM here
    // const response = await llm.complete(prompt);
    // return JSON.parse(response);

    // Simplified for illustration
    if (iteration === 0) {
      return { nextAgent: 'researcher', taskForAgent: 'Research the topic', reason: 'Need facts first' };
    } else if (iteration === 1) {
      return { nextAgent: 'coder', taskForAgent: 'Write code', reason: 'Need implementation' };
    } else if (iteration === 2) {
      return { nextAgent: 'reviewer', taskForAgent: 'Review the code', reason: 'Need quality check' };
    }
    return { nextAgent: 'DONE', taskForAgent: 'Task complete', reason: 'All steps done' };
  }

  getConversationLog(): ConversationTurn[] {
    return [...this.conversationLog];
  }
}

// Usage
const supervisor = new HierarchicalSupervisor({
  maxIterations: 8,
  maxTokens: 80_000,
  specialists: [
    { name: 'researcher', description: 'Finds information and facts', execute: async (t) => 'RESEARCH: ...' },
    { name: 'coder', description: 'Writes and modifies code', execute: async (t) => 'CODE: ...' },
    { name: 'reviewer', description: 'Reviews code for bugs and security', execute: async (t) => 'REVIEW: ...' },
    { name: 'writer', description: 'Writes documentation and prose', execute: async (t) => 'DOCS: ...' },
  ],
});

const result = await supervisor.run('Build a REST API endpoint that fetches user preferences');
console.log(`Completed in ${result.turns.length} turns, ${result.tokensUsed} tokens`);
console.log('Agent trace:', result.turns.map(t => `${t.agent}(${t.timestamp}ms)`).join(' -> '));

Complexity: Medium   Flexibility: High   Observability: High (single entry point, logged turns)

Tradeoff: The supervisor itself consumes tokens on every routing decision. With 8 iterations, the supervisor makes 8 LLM calls just for routing. This overhead is acceptable for complex tasks but wasteful for simple ones.

Pattern 4: Peer-to-Peer Handoff

Agents communicate directly with each other without a central supervisor. When an agent encounters a task outside its expertise, it hands off to another agent with a context summary. This is the pattern used by OpenAI Swarm — agents can call transfer_to_agent() to delegate.

When to Use

  • Agents have well-defined specialties and can recognize when to hand off
  • You want emergent, flexible routing without a centralized bottleneck
  • The conversation is conversational (user might interact with multiple agents in one session)

Implementation

/**
 * Peer-to-Peer Handoff Pattern
 * Agents transfer control to each other with context summaries.
 * Includes cycle detection and max handoff depth.
 */

interface HandoffResult {
  finalAgent: string;
  response: string;
  handoffChain: string[];
  totalTokens: number;
}

interface HandoffAgent {
  name: string;
  systemPrompt: string;
  // Returns either a direct response OR a handoff directive
  handle: (
    message: string,
    context: string,
    availableAgents: string[]
  ) => Promise<{ type: 'respond'; content: string } | { type: 'handoff'; target: string; summary: string }>;
}

class PeerToPeerHandoff {
  private agents: Map<string, HandoffAgent>;
  private maxHandoffs: number;
  private maxHandoffDepth: number;
  private visitedAgents: Set<string> = new Set();

  constructor(options: {
    agents: HandoffAgent[];
    maxHandoffs?: number;
    maxHandoffDepth?: number;
  }) {
    this.agents = new Map(options.agents.map(a => [a.name, a]));
    this.maxHandoffs = options.maxHandoffs ?? 6;
    this.maxHandoffDepth = options.maxHandoffDepth ?? 3;
  }

  async run(
    initialMessage: string,
    startAgent: string
  ): Promise<HandoffResult> {
    let currentAgent = startAgent;
    let message = initialMessage;
    let context = '';
    const handoffChain: string[] = [startAgent];
    let totalTokens = 0;
    let handoffCount = 0;

    while (handoffCount < this.maxHandoffs) {
      const agent = this.agents.get(currentAgent);
      if (!agent) {
        throw new Error(`Unknown agent: ${currentAgent}`);
      }

      // Cycle detection: if we've visited this agent before in this chain,
      // we're in a loop — break it
      if (this.visitedAgents.has(currentAgent) && handoffCount > 0) {
        console.warn(`Cycle detected: agent ${currentAgent} visited twice. Breaking.`);
        break;
      }
      this.visitedAgents.add(currentAgent);

      const availableAgents = Array.from(this.agents.keys())
        .filter(n => n !== currentAgent);

      const result = await agent.handle(message, context, availableAgents);
      const tokens = Math.ceil((message.length + context.length) / 4);
      totalTokens += tokens;

      if (result.type === 'respond') {
        // Agent produced a final answer
        return { finalAgent: currentAgent, response: result.content, handoffChain, totalTokens };
      }

      // Agent requested handoff
      handoffCount++;
      context += `\n[Handoff from ${currentAgent} to ${result.target}]: ${result.summary}`;

      // Depth guard
      if (handoffCount >= this.maxHandoffDepth) {
        return {
          finalAgent: currentAgent,
          response: `Max handoff depth (${this.maxHandoffDepth}) reached. Last context: ${context.slice(-500)}`,
          handoffChain,
          totalTokens,
        };
      }

      handoffChain.push(result.target);
      message = result.summary; // next agent gets the summary, not the original
      currentAgent = result.target;
    }

    return {
      finalAgent: currentAgent,
      response: `Max handoffs (${this.maxHandoffs}) reached without resolution.`,
      handoffChain,
      totalTokens,
    };
  }
}

// Usage: Customer support with triage -> billing -> technical
const p2p = new PeerToPeerHandoff({
  maxHandoffs: 6,
  maxHandoffDepth: 4,
  agents: [
    {
      name: 'triage',
      systemPrompt: 'Route customer queries to the right team.',
      handle: async (msg, ctx, available) => {
        if (msg.includes('refund') || msg.includes('charge')) {

        }
        if (msg.includes('error') || msg.includes('bug')) {
          return { type: 'handoff', target: 'technical', summary: `Customer reports: ${msg.slice(0, 200)}` };
        }
        return { type: 'respond', content: 'How can I help you today?' };
      },
    },
    {
      name: 'billing',
      systemPrompt: 'Handle billing and refund queries.',
      handle: async (msg, ctx, available) => {
        return { type: 'respond', content: 'I can process your refund. Please provide your order ID.' };
      },
    },
    {
      name: 'technical',
      systemPrompt: 'Handle technical issues and bug reports.',
      handle: async (msg, ctx, available) => {
        return { type: 'respond', content: 'Let me look into this error for you.' };
      },
    },
  ],

Complexity: Medium   Flexibility: High   Cycle Risk: High (requires cycle detection)

Critical guard: Without cycle detection and max-depth limits, peer-to-peer handoffs can loop infinitely — Agent A hands off to Agent B, which hands back to Agent A. Always track visited agents and enforce a hard ceiling.

Pattern 5: Auction-Based Task Allocation

Instead of a supervisor deciding who does what, each agent "bids" on tasks based on its self-assessed capability and availability. The highest bidder wins the task. This is useful when agents have varying specializations and you want emergent task assignment without a central router.

When to Use

  • Agents have overlapping but non-identical capabilities
  • You want load balancing across agents
  • Task assignment should be dynamic, not hardcoded
  • Multiple agents could plausibly handle a task, and the "best" one varies

Implementation

/**
 * Auction-Based Task Allocation Pattern
 * Agents bid on tasks; highest bidder wins.
 * Uses a simple capability scoring function.
 */

interface Bid {
  agentName: string;
  score: number;   // 0-1 confidence
  reason: string;
}

interface Task {
  id: string;
  description: string;
  type: string;
  priority: number;
}

interface AuctionAgent {
  name: string;
  bid: (task: Task) => Promise<Bid>;
  execute: (task: Task) => Promise<string>;
  currentLoad: number;  // number of tasks currently assigned
  maxLoad: number;      // max concurrent tasks
}

class AuctionAllocator {
  private agents: AuctionAgent[];
  private taskLog: { task: Task; winner: string; bids: Bid[] }[] = [];

  constructor(agents: AuctionAgent[]) {
    this.agents = agents;
  }

  async allocateAndExecute(tasks: Task[]): Promise<Map<string, string>> {
    const results = new Map<string, string>();

    // Sort by priority (highest first)
    const sorted = [...tasks].sort((a, b) => b.priority - a.priority);

    for (const task of sorted) {
      // Collect bids from all available agents
      const availableAgents = this.agents.filter(a => a.currentLoad < a.maxLoad);

      if (availableAgents.length === 0) {
        results.set(task.id, `NO_AVAILABLE_AGENT: all agents at max load`);
        continue;
      }

      const bids = await Promise.all(
        availableAgents.map(a => a.bid(task))
      );

      // Winner = highest score
      const sortedBids = bids.sort((a, b) => b.score - a.score);
      const winner = sortedBids[0];

      if (winner.score <= 0) {
        results.set(task.id, `NO_BIDDER: no agent could handle this task`);
        continue;
      }

      // Execute
      const winningAgent = this.agents.find(a => a.name === winner.agentName)!;
      winningAgent.currentLoad++;

      this.taskLog.push({ task, winner: winner.agentName, bids: sortedBids });

      try {
        const output = await winningAgent.execute(task);
        results.set(task.id, output);
      } catch (err) {
        // Re-auction: try the next bidder
        const runnerUp = sortedBids[1];
        if (runnerUp && runnerUp.score > 0) {
          const altAgent = this.agents.find(a => a.name === runnerUp.agentName)!;
          const altOutput = await altAgent.execute(task);
          results.set(task.id, `[RECOVERED via ${runnerUp.agentName}] ${altOutput}`);
        } else {
          results.set(task.id, `EXECUTION_FAILED: ${(err as Error).message}`);
        }
      } finally {
        winningAgent.currentLoad--;
      }
    }

    return results;
  }

  getAllocationLog() {
    return this.taskLog;
  }
}

  { id: 't2', description: 'Center a div', type: 'css', priority: 1 },
]);
console.log(allocator.getAllocationLog().map(l => `${l.task.id} -> ${l.winner} (${l.bids[0].score})`));

Complexity: Medium   Load Balancing: Good   Token Cost: Medium (bidding overhead)

Pattern 6: Event-Driven Choreography

There is no central coordinator. Instead, agents subscribe to an event bus and react to events. When an agent completes work, it publishes an event; other agents that are interested in that event type pick it up and process it. This is the most decentralized pattern — closest to how microservices work in distributed systems.

When to Use

  • Tasks are reactive (triggered by external events, webhooks, or scheduled triggers)
  • Multiple independent agent workflows need to coexist
  • You need loose coupling between agents (add/remove agents without rewiring)
  • The system is long-running (agents live as services, not one-shot invocations)

Implementation

/**
 * Event-Driven Choreography Pattern
 * Agents subscribe to events on a shared bus.
 * No central coordinator; agents react independently.
 */

type EventType =
  | 'user_request'
  | 'research_complete'
  | 'code_generated'
  | 'review_passed'
  | 'review_failed'
  | 'task_complete';

interface AgentEvent {
  type: EventType;
  payload: any;
  source: string;
  timestamp: number;
  correlationId: string;  // tracks a single user request across agents
}

type EventHandler = (event: AgentEvent) => Promise<void>;

class EventBus {
  private handlers: Map<EventType, EventHandler[]> = new Map();
  private eventLog: AgentEvent[] = [];
  private maxLogSize: number;

  constructor(maxLogSize: number = 10_000) {
    this.maxLogSize = maxLogSize;
  }

  subscribe(eventType: EventType, handler: EventHandler): void {
    if (!this.handlers.has(eventType)) {
      this.handlers.set(eventType, []);
    }
    this.handlers.get(eventType)!.push(handler);
  }

  async publish(event: AgentEvent): Promise<void> {
    this.eventLog.push(event);
    if (this.eventLog.length > this.maxLogSize) {
      this.eventLog.shift();  // ring buffer
    }

    const handlers = this.handlers.get(event.type) ?? [];
    // Fire all handlers in parallel; collect errors
    const results = await Promise.allSettled(
      handlers.map(h => h(event))
    );

    // Log handler failures without crashing the bus
    for (let i = 0; i < results.length; i++) {
      if (results[i].status === 'rejected') {
        console.error(
          `Handler ${i} failed for event ${event.type} ` +
          `(correlationId=${event.correlationId}): ${(results[i] as any).reason}`
        );
      }
    }
  }

  getEventLog(correlationId?: string): AgentEvent[] {
    if (correlationId) {
      return this.eventLog.filter(e => e.correlationId === correlationId);
    }
    return [...this.eventLog];
  }
}

// Usage: Research -> Code -> Review pipeline via events
const bus = new EventBus();

// Researcher subscribes to user requests
bus.subscribe('user_request', async (event) => {
  const research = `Research on: ${event.payload.query}`;
  await bus.publish({
    type: 'research_complete',
    payload: { research },
    source: 'researcher',
    timestamp: Date.now(),
    correlationId: event.correlationId,
  });
});

// Coder subscribes to research completion
bus.subscribe('research_complete', async (event) => {
  const code = `Implementation based on: ${event.payload.research.slice(0, 100)}`;
  await bus.publish({
    type: 'code_generated',
    payload: { code },
    source: 'coder',
    timestamp: Date.now(),
    correlationId: event.correlationId,
  });
});

// Reviewer subscribes to code generation
bus.subscribe('code_generated', async (event) => {
  const passed = Math.random() > 0.3;  // simulate review
  await bus.publish({
    type: passed ? 'review_passed' : 'review_failed',
    payload: { code: event.payload.code, issues: passed ? [] : ['missing tests'] },
    source: 'reviewer',
    timestamp: Date.now(),
    correlationId: event.correlationId,
  });
});

// On failure, coder gets another chance
bus.subscribe('review_failed', async (event) => {
  await bus.publish({
    type: 'research_complete',  // re-trigger the coder
    payload: { research: `Fix issues: ${event.payload.issues.join(', ')}` },
    source: 'reviewer',
    timestamp: Date.now(),
    correlationId: event.correlationId,
  });
});

// Kick off a request
await bus.publish({
  type: 'user_request',
  payload: { query: 'Build a rate limiter' },
  source: 'user',
  timestamp: Date.now(),
  correlationId: 'req-001',
});

// Trace the full event chain
const trace = bus.getEventLog('req-001');
console.log(`Event chain for req-001: ${trace.map(e => e.type).join(' -> ')}`);

Complexity: High   Decoupling: Maximum   Observability: Medium (requires correlation IDs)

Tradeoff: Event-driven systems are harder to debug because there's no single call stack. A user request might trigger a chain of 15 events across 6 agents, and reconstructing "what happened" requires careful correlation ID tracking. But for long-running, reactive systems, this is the most scalable pattern.

Anti-Pattern 1: Uncontrolled Recursive Delegation

🚨 What Goes Wrong

Agent A decides it needs help, so it spawns Agent B. Agent B decides it needs help, so it spawns Agent C. Agent C hands back to Agent A for "more context." Before you know it, you have 50 agents running, each consuming a full context window, in an infinite delegation loop. This is the #1 failure mode in multi-agent systems.

The fix: Always enforce a max delegation depth (typically 2-3 levels) and a max total token budget. Track the delegation chain and reject any agent that tries to delegate back to an agent already in its ancestry chain.

// BAD: No depth limit, no cycle detection
async function badDelegate(agent, task) {
  const result = await agent.handle(task);
  if (result.type === 'delegate') {
    return badDelegate(getAgent(result.target), result.task);  // 👉 infinite loop risk
  }
  return result;
}

// GOOD: Depth limit + visited set + token budget
async function safeDelegate(agent, task, depth = 0, visited = new Set(), budget = { tokens: 0, max: 50_000 }) {
  if (depth >= 3) throw new Error('Max delegation depth exceeded');
  if (visited.has(agent.name)) throw new Error(`Cycle detected: ${agent.name}`);
  if (budget.tokens >= budget.max) throw new Error('Token budget exhausted');

  visited.add(agent.name);
  const result = await agent.handle(task);
  budget.tokens += Math.ceil(result.output.length / 4);

  if (result.type === 'delegate') {
    return safeDelegate(getAgent(result.target), result.task, depth + 1, visited, budget);
  }
  return result;
}

Anti-Pattern 2: Shared Mutable State Without Coordination

When multiple agents read and write to the same shared state object (e.g., a shared document, a shared codebase, or a shared database), you get race conditions. Agent A writes a paragraph while Agent B simultaneously deletes the section containing it. The result is corrupted state that neither agent intended.

The fix: Use one of three approaches: (1) immutable snapshots — each agent receives a read-only copy and produces a new version; (2) explicit locks — only one agent can modify state at a time, with a timeout; (3) event sourcing — agents emit intent events, and a single reducer applies them sequentially.

Anti-Pattern 3: No Correlation ID for Tracing

In event-driven or supervisor patterns, a single user request might flow through 5+ agents. Without a correlation ID threaded through every event and log entry, you cannot reconstruct which agents processed a given request, in what order, or where it failed. This makes debugging impossible.

The fix: Generate a UUID at request entry, attach it to every agent invocation, every event, and every log line. At debug time, grep for the correlation ID to see the full trace.

// Generate at request entry
const correlationId = crypto.randomUUID();

// Thread through every agent call
await supervisor.run({
  request: userRequest,
  correlationId,  // 👉 appears in every downstream event
});

// In logs:
// [req-abc123] supervisor -> researcher: "Find facts about X"
// [req-abc123] researcher -> supervisor: "Found 3 facts"
// [req-abc123] supervisor -> coder: "Write code based on facts"
// [req-abc123] coder -> supervisor: "Wrote function Y"
// [req-abc123] supervisor -> DONE

Anti-Pattern 4: Uniform Model Selection

Using the same LLM for every agent in the system. A researcher agent that reads documents doesn't need GPT-4 — a cheaper model like GPT-4o-mini or Claude Haiku is sufficient. But a code generation agent might need the strongest reasoning model available. Uniform model selection wastes money on overpowered models for simple tasks and underpowers agents that need strong reasoning.

The fix: Assign models per agent based on task complexity. Research/triage agents use small/fast models. Code/reasoning agents use large/smart models. The supervisor uses a medium model (it needs to reason about routing but not generate complex output).

Decision Framework: Which Pattern Should You Use?

  1. Is your workflow fixed and linear? → Sequential Pipeline
  2. Can sub-tasks run independently? → Fan-Out / Fan-In
  3. Do you need dynamic routing? → Hierarchical Supervisor
  4. Is it conversational with handoffs? → Peer-to-Peer Handoff
  5. Do you have a pool of specialists? → Auction-Based
  6. Is it reactive/long-running? → Event-Driven Choreography

Most production systems start with Pattern 1 (Sequential Pipeline) and evolve to Pattern 3 (Hierarchical Supervisor) as complexity grows. Patterns 4-6 are for advanced use cases where the simpler patterns cannot meet the requirements.

Essential Guardrails for Every Multi-Agent System

Regardless of which pattern you choose, every multi-agent system needs these guardrails:

  • Max iterations / handoffs: Hard ceiling on how many agent invocations a single request can trigger (typically 5-15)
  • Total token budget: Aggregate cap across all agents (typically 50K-100K tokens per user request)
  • Per-agent timeout: No single agent should run for more than 30-60 seconds
  • Correlation ID: UUID threaded through every event for traceability
  • Cycle detection: Track visited agents and reject cycles
  • Graceful degradation: If an agent fails, the system should degrade, not crash — see our guide to graceful degradation patterns

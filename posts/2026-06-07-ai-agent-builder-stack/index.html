5 jobs (one paragraph each)

Every agent builder I have talked to does the same five things, in some order, with some overlap. The 8 tools in this stack are grouped by which job they help with.

  1. Scaffold the server. Before you can iterate on the agent, you need a working MCP server with tools, schemas, and tests. The MCP Server Starter Kit ships 9 tools across 3 servers (a file system server, a notes server, a calculator server), with 210 tests in a node test/run-all.js runner, zero dependencies, and an MIT license. You can fork one of the three servers, swap the tools, and ship a production-shaped MCP server in under five minutes.
  2. Validate it works. A passing build is not the same as a correct MCP server. The MCP Server Tester is a grade-A+ to F linter that checks tool shapes, schema validity, response performance, and error handling. It runs against any local MCP server with --json output and --fail-on D for CI gating, and it tells you exactly which dimension failed and how to fix it.
  3. Audit the agent config. Agent configs drift. Permissions creep, prompt-injection vectors accumulate, and one bad file can exfiltrate the whole session. Three tools cover three different lenses: Agent Safety Audit (36 patterns across 9 categories, vulnerability-focused), AgentLint (17 best-practice rules, style and correctness), and MCP Supply Chain Audit (10 patterns for unverified sources, tool shadowing, role overrides). All three output JSON, all three have --fail-on flags, and all three are independent enough that you can run all three in parallel and merge the findings.
  4. Guard the runtime. Pre-built guards stop rm -rf /, redact .env reads, log bash commands, and emit session context before damage is done. The Claude Code Hook Pack ships 4 production-ready hook JSONs (block-rm-rf, log-bash-commands, session-context, secret-redact-warning) plus a zero-dependency CLI for install / test / list / remove in ~/.claude/settings.json. The CLI has a 41-test self-test and a --dry-run preview, so you can see exactly which lines get appended before any file is touched.
  5. Preserve context and verify the output. Agent state evaporates on restart. Generated code can hallucinate APIs. Two tools cover both sides of the lifecycle: Agent Continuity Kit captures, redacts, and restores session context across restarts, and Vibe Verify checks AI-generated code against an intent document and catches hallucinated APIs, wrong imports, and subtle logic errors before they hit a PR.

What's not in this stack

This is an agent builder's stack, not a security operator's stack. If you need MCP Poison Scanner (detects tool-poisoning in live MCP server configs), v0 Prompt-Leak Scanner (catches prompt-leak patterns in v0 / Vercel AI SDK / Next.js apps), Bounty Hunter Kit (PoC scaffolding for security bounties), Security Pattern Detector (15 anti-patterns in codebases), or Env Audit (.env vulnerability scanner), those are in the security-team cut instead. The two cuts cross-link at the end of each post.

This is also not a hosting or runtime stack. The 8 tools run locally, in CI, or in a developer shell. They are not a managed MCP server, a hosted agent runtime, or a remote LLM gateway. They are CLIs you can run before the agent exists, while it is being built, after every config change, and on every deploy.
